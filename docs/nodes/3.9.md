Use `scripts/node_check.py` outside any Broadsword job: it captures each block

from the root `broadsword.toml` setting `done_check_timeout_seconds`; never

For task verification, record the equivalent command with `--task <id>` after
the project name. Pin the tested worktree to the judged commit and record its

Every automated block requires exit zero, the named test actually executed,
nonempty labelled case counts and no ignored/skipped cases. Missing fixtures,
unsupported versions, non-finite measurements, timeout, refusal, partial output
or unavailable required hardware are failures, not passes. The runner's
`contains` rule detects an explicit labelled completion marker printed only
after all assertions; assertions enforce the full rule below.
Human check r7 must not be counted as automated approval.

All tolerance, size/work caps, sampling schedules and paths are required
settings established by R2 before viewing implementation results. No silent
defaults. Draft correctness budgets: dimensionless weight-sum error at most
`1e-6`; position and planted-foot drift at most `1e-4` of the fixture's
positive rest-pose height; quaternion angular error at most `1e-4` radians
using sign-invariant rotation distance. These are engineering proposals for
Lazlo, not published rigging standards: they allow floating-point roundoff
while detecting visibly misplaced joints or unnormalised skinning. R3 must
establish independent reference uncertainty below each adopted budget.
For loop derivatives, compare with time normalized to one cycle: propose
`1e-4` rest heights per cycle for translational velocity and `1e-4` radians
per cycle for angular velocity, so an endpoint pose match cannot hide a jerk.
Propose swing clearance at least `0.01` rest heights at the designated
mid-swing samples, to reject a stationary or ground-dragging foot. These
are likewise configurable draft engineering budgets, not gait research data.
Fixture height, coordinate band and angle/time conventions are frozen first.
Counts and identity checks are exact, not tolerance comparisons.

## 2. Home

Proposed home: the **separate `animation-core` repository** proposed by node
2.6, with library crate/package `rigging-tools` at `crates/rigging-tools/`.
R1 adds that member to the repo's workspace. Skeletons, skinning, curves and
IK remain owned by the root `animation-core` crate, used by an intra-repo
member dependency. Rig editing commands, control bindings and authoring
project format belong to `rigging-tools`. This does not create another repo
or put workload code in the Broadsword platform repo.

ADR 0001 option (a) remains binding: separate repos; **file formats are the
contract; no Cargo dependency (path or git) on another repo without a new
ADR, which is Lazlo's call.** The member path stays inside this one repo in
both main and task worktrees. Never plan a link into `projects/foundation`.
R1 checks the resolved dependency inventory, including dev/build dependencies
and local overrides, for escapes. No symlink/junction workaround.

Node 2.9 contributes reviewed constraint diagnostic cases via versioned
files, not its Rust solver. A 2D sketch solver is not a 3D rig constraint
solver. R6 uses 2.6's local IK and small ordered rig constraints; it does not
promise arbitrary nonlinear 3D constraint solving.

**ADR triggers, not permissions:** needing animation evaluation in-process
from a *different* repo fires ADR 0001 trigger 1 (second project needs a
library, by analogy with its sim example). Reusing another repo's math/parser
fires trigger 2 (third Rust consumer); sharing node 2.8's numerical solver
with 2.9 fires trigger 4 (numerics needed by two projects). Stop for Lazlo's
new ADR/migration decision, rather than adding a dependency. Keeping rigging
beside animation avoids these new edges but does not waive the unresolved
math-sharing triggers already recorded by node 2.6.

`docs/adr/0004-roadmap-repo-map.md` is **Proposed**, not authorisation.
If accepted, its W/model home may replace this layout; shared constraint
services would go through core, never model -> CAD internals. Live use of
shell/renderer code currently in other repos also requires the new ADR first.
For the isolated draft, R10 proposes approved third-party Rust window/pixel
crates and a CPU preview over local animation data, not cross-repo UI links.
Rewrite commands and claims if Lazlo instead chooses the shared workspace.

R3 authors a simple bilateral biped mesh with pelvis, torso, head, arms and
leg/foot chains, initially with **no skeleton, weights, constraints or keys**.
Document axes, handedness, units, rest height, joint/control identity,
rotation order, contact intervals and loop derivative convention. References
use rational/analytic small cases and independently evaluated high-precision
values with recorded method/uncertainty; an independent reviewer verifies
them before candidate results exist. In-place walking deliberately avoids
root-displacement seam ambiguity. No imported mocap is an oracle.

Required adversarial coverage, allocated to R2 and the owning feature brief:
empty/duplicate IDs, invalid parent indices, cycles, zero-length bones,
singular bind transforms, NaN/inf, signed/overflowing counts, negative and
zero-sum weights, duplicate timestamps, invalid duration, tiny/large and
near-cancelling valid transforms. Bound floats in constructors and check
finiteness of the values about to be committed, once before state changes.
Test boundary arithmetic against R3's independent references, including
subnormals where accepted; otherwise return a named out-of-band error.

Parsers must reject huge/truncated files, duplicate/unknown fields and hostile
comments/strings according to the documented grammar; define CRLF handling
and reject other unexpected line breaks. Bound bytes/counts before allocation
and total graph/evaluation work in the common lower-level entry point.
Report the first error, never silent coercion or partial project mutation.
Saved projects embed data rather than following external asset paths.
Output paths come from settings, stay relative under scratch, reject drive,
UNC, `..` and link escapes (including Windows backslashes); test a replaced
link at write time and partial-write failure, preserving prior bytes.

R4-R8 each supply a behavioural mutation demonstration during implementation:
disable respectively a cycle guard, normalization, constraint evaluation,
control mapping or transactional load, observe the named assertion fail,
restore and re-read the diff. R9's committed negative cases additionally
prove acceptance rejects a static/drifting/broken loop without compiler errors.
No new child-process runner is planned; existing node-check timeout handles
the Broadsword command tree. If R10 introduces helpers, it needs a separate
bounded lifecycle/held-pipe test brief before use.

## 8. Risks and size

- **Unbuilt prerequisites:** both mandatory nodes are not started. Their
  APIs/formats and 2.6's own dependency decisions can invalidate the home,
  commands and fixture plan. Stop implementation, not planning, until settled.
- **Architecture decision:** accepted ADR 0001 and proposed ADR 0004 differ
  in eventual home. Do not treat proposed W/model as an existing workspace;
  no cross-repo dependency or foundation link is a workaround.
- **2D versus 3D constraints:** diagnostic contracts do not provide arbitrary
  rig solving. If the biped needs a general iterative solver, add a separately
  approved design/brief sequence and consider ADR 0001 trigger 4.
- **Reference bias:** a self-generated walk may validate the same wrong
  convention twice. Freeze independent analytic values/contact semantics,
  test negative controls, and require Lazlo's visual verdict.
- **Walk quality:** passing numeric seams is not sufficient for convincing
  locomotion. Human deformation/contact findings remain open failures;
  no imported clip or baked pose stream may substitute for authoring.
- **UI size and external needs:** full picking/painting/keying is unlikely
  to fit the adapter seed. Split it before dispatch, keep headless commands
  shared, and approve host crates/licences. A locked desktop blocks r7.
- **Resource use:** skinning, overlays and evidence can exhaust shared
  RAM/GPU memory or scratch. Enforce configured work/output bounds, retain
  accepted evidence outside ephemeral scratch, and involve Lazlo first.
- **Evidence and status drift:** this is not verified capability; the docs
  task does not change `ROADMAP.md`. Recheck statuses, licences, tested SHA
  and exact commands at node start. Preserve all blockers until resolved.

**Size estimate:** roughly 16-24 implementation/review briefs to reach the
complete Done-when, including the setup seeds, UI splits and likely fix
rounds; an estimate, not an arithmetic total or measured throughput.
No elapsed-time, line-total or FPS prediction is made. Main-project work
always preempts these briefs.

## 1. Done checks as commands

These are **future commands**, not claims about an existing executable. Section 7
assigns every project, example, case and test below to a brief. All run from the
Broadsword root; all evidence goes to distinct files under `scratch/`. Inside a
coding task, add the task selector after the project name. No direct cargo runs.
The existing `scripts/node_check.py` reads the `check <id>` fences; the roadmap
check reader can extract the same command/PASS pairs.

Use that runner one check at a time, outside any Broadsword job, with its explicit
timeout taken from `done_check_timeout_seconds` in `broadsword.toml`; do not nest
Broadsword jobs. It applies a process-tree timeout to each external run. The
blocks deliberately contain no shell pipelines, directory changes or compound
redirects. Preserve the command's exit code as well as its output. Every positive
check needs exit 0 and its stated evidence; empty output, missing tests, refusal,
timeout, cut-off output, unavailable servers and skipped cases are FAIL, not PASS.
`contains` rules below are supported by the existing reader. Free-text human
rules need Lazlo and are never automatically counted as passes.
Direct invocation uses the shown redirect; `node_check.py` instead captures to
`scratch/node-checks/2.10/<id>.txt` and strips that redirect. Retain whichever
actual evidence path was produced. Only the driver judge emits success markers;
untrusted server/host text must never be copied as a standalone marker line.

## 2. Home

Proposed initial home: **separate repo `projects/code-editor`, one crate
`code-editor` (Rust library plus `editorcheck` example), detached `[workspace]`.**
Lazlo approves the repo before the orchestrator creates it; this task creates
nothing but this plan. All paths resolve through settings, never an absolute path.

ADR 0001, Accepted option (a): separate repos; **file formats are the contract;
no Cargo dependency (path or git) on another repo without a new ADR, Lazlo's
call. Never plan a link into `projects/foundation`.** The editor owns its text,
selection and document-version types. It exchanges versioned UTF-8 edit events,
viewport requests, styled spans and frame acknowledgments as data with hosts;
LSP is a separate specified process protocol. Vendor only approved third-party
packages, not sibling-repo code disguised as vendored code.

For actual use of 1.4/1.5 code **in process**, the analogous ADR 0001 trigger 1
("a second project must run ... as a library") fires, as already identified in
`docs/nodes/1.4.md` section 2 and `docs/nodes/1.5.md` section 2. Ask Lazlo for the
new ADR (the proposed ADR 0002 move to option d2); it is not accepted or even
present in `docs/adr/` here. Do not add path/git dependencies as a workaround.

The initial plan instead proposes an **out-of-process data host** for P10.
Its versioned file/pipe contract must be agreed with 1.4/1.5 before P2; this plan
does not assert their existing plans supply that executable or protocol. If the
host cannot meet timing or live-editing requirements, stop P10 and seek the ADR,
then rewrite the home and integration briefs. No unapproved cross-repo link is
planned. Copying window/text internals is not the fallback.

`docs/adr/0004-roadmap-repo-map.md:114` proposes `W/dev`, not this separate home.
That ADR is **Proposed**, not authority to merge repos. Its revision rule requires
a follow-up to reconcile that row when Lazlo decides the home; that file is
outside this task's claim. This divergence is open, not silently resolved.

## 5. Test harness

P2 freezes interfaces and named errors first; P3 creates deterministic fixtures,
independent expected data and CLI wiring before the implementation briefs.
No skeleton may print success for unimplemented cases. All example cases share
one judge and one validated settings constructor. Raw metrics precede PASS
markers; errors retain the first cause and return nonzero even during cleanup.

| Check | Proof and fixtures to create |
| --- | --- |
| e1 | Property-style seeded edit traces against a separate flat-string oracle; empty/no-final-newline, LF/CRLF, BOM, mixed scripts, combining characters, non-BMP text and one long line. Byte-identical no-edit saves. Explicitly reject unsupported/invalid encodings without changing the file. |
| e2 | Handwritten before/after transaction goldens: adjacent, overlapping, duplicate and reversed selections, cursor at EOF, selections crossing lines, paste and undo/redo. Define offsets in original-document order and deterministic overlap policy before code. Compare bytes, cursors and revision. Disable overlap normalization: the overlap case must report a mismatch or named rejection rather than PASS. |
| e3 | Small original Rust and approved LL snippets with reviewed capture spans; comments containing quotes, raw strings, escapes, malformed syntax and edits shifting later lines. Goldens are not generated from the highlighter under test. Disabling incremental invalidation must fail the edited-string case. |
| e4 | Scripted in-memory and real-child fake-peer transcripts: split headers/body, coalesced messages, duplicate/overflow/negative lengths, invalid JSON, duplicate keys, excessive depth, notifications, wrong IDs, empty replies, late/cancelled replies, version races, UTF-16 surrogate boundaries and unsupported encoding. A fake peer that returns the pre-edit range must be rejected after a change. |
| e5 | Generate ordinary-line and long-line files deterministically into configured scratch workspaces; print seed, size and digest. Independently verify edits against a streamed reference, outside timed intervals. Include full-file hashing before/after undo. Measure file open, edit pipeline and peak process memory, not a preloaded buffer or just insertion into an unused rope. |
| e6/e7 | Original tiny two-file workspaces, explicit completion label and definition coordinates in a manifest, independent Unicode position table and post-edit coordinates. Print server version/digest, requests and scrubbed response evidence. Verify resolved definition bytes at the actual target; never take expected ranges from a server response. No network dependency resolution. |
| e8 | Real host, real text renderer, input trace, visible-frame acknowledgments and Lazlo's signed-off observation. Scroll/edit near the start and end of each large fixture; verify displayed text against the independent expected content. Timer ends only after host acknowledgment, never on buffer mutation. |
| e9 | Unit tests of the shared measurement judge for exact boundary, over-budget, missing/empty, NaN/inf, negative and overflowed metrics; independently supplied labelled samples. Dropping the stall comparison must make the above-stall sample incorrectly pass and thus fail this test. |

Hostile tests start in the owning brief, not after integration: configured huge
files/pastes/cursor sets; oversized JSON/header/stderr; a child/grandchild keeping
pipes open after timeout; spawn failure, EOF half-message and shutdown failure.
All server and host spawns share one bounded supervisor, keyed by the actual
resource when locking a shared executable/workspace, not just a language label.
Use OS process-tree containment and drain/cap streams without hanging; protocol
stdout is not a log. A cap breach is an error, not a truncated successful reply.
Do not log arbitrary source/secrets; sanitize before any evidence truncation.

Validate at the lowest boundary used by every caller: signs, checked integer
arithmetic, UTF boundaries, JSON depth and message sizes, URI percent-decoding,
drive-letter/Windows backslash forms, CR/control characters and workspace escape.
Use handles/atomic replacement where writing files; test a path changed to a
link between validation and use. Never follow a link out of the configured
workspace. A failed open/edit/save leaves original bytes and document state
intact; test partial writes and disk-full via a controlled writer. No recursive
cleanup of arbitrary paths. All test artifacts stay in per-check scratch
workspaces; no real user projects, `.env`, settings or network are touched.

Timings use integer durations; memory and offsets use checked integers. Any
derived floating metric must be finite before judgment and cannot mutate state.
Thresholds come from required settings, never literals scattered through tests.
Property-test counts and safety bounds are likewise configured, not unbounded.
Record the exact revision under test; comparing evidence from another revision
does not judge this one. Behavioural negative controls are restored before review.

## 8. Risks and size

- **Undefined LL ecosystem:** roadmap names a language but supplies no grammar,
  server URL or licence. Carry this blocker until Lazlo supplies them. If a new
  server must be built, that is separate language-project work of unknown size;
  node 2.10 cannot truthfully finish e7 without it.
- **Integration/home decision:** separate data-host processes may cost latency
  or fail the live-editor requirement. Trigger 1 and the ADR 0002 decision are
  explicit in section 2; ADR 0004's W/dev row reconciliation also stays open.
  In-process code reuse waits for approval, never a path/git link workaround.
- **Dependency exception:** tree-sitter is C-backed; ADR 0003 is not accepted.
  Approvals, licence review, C compiler portability and vendoring can delay
  P2/P6 even though writing this plan needed no dependency.
- **Size and benchmarks:** 100 MB means decimal bytes here, but ordinary lines
  alone miss huge-line, Unicode and paste costs. Section 5 exercises those;
  e8 and peak memory prevent a fast unused buffer from satisfying smooth editing.
  Shared GPU/system RAM and busy boards invalidate comparisons. Proposed budgets
  require Lazlo approval; a genuine failure is reported, not silently relaxed.
- **LSP realism/security:** real-server outputs vary with pins; fixtures must
  avoid dependencies and compare semantic targets, not full unstable lists.
  URI decoding, stale versions, untrusted server text and descendant processes
  need the lower-boundary guards/tests in P7/P8. Never run against user projects.
- **Slice estimates:** P7/P8/P10 are likely to exceed the target once platform
  containment, encoding and host APIs are known. Split into reviewed briefs with
  explicit claims before assignment. No skeleton/not-ready case counts as a
  delivered feature, and generated output is not independent reference data.

**Rough size, estimates only:** P1-P10 are the initial brief seeds. Allow a further
small batch of follow-ups for lifecycle/encoding edge cases, host integration,
vendoring and independent review fixes: roughly **15–25 briefs to Done-when**
if both language servers and prerequisite host already exist. This is a planning
range, not a computed progress count or measured throughput. Building a missing
LL server or carrying out the workload-repo ADR is excluded and unestimated.

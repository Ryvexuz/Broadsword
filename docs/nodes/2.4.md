## 1. Done checks as commands

### How to run and read a check

- Run every command from the Broadsword root. `broadsword` means `build/bin/broadsword.exe`. Inside a task, add `--task <id>` after the project name.
- Never call cargo directly. Tests go through `broadsword test scene`; a program goes through `broadsword run scene -- cargo run --offline --release --example <name> -- <flags>`. This is the same form as `docs/nodes/1.1.md` section 1.
- Every command writes to a file in `scratch/` (`> scratch/<file> 2>&1`); read the file. A program writes its result to stdout, so the program's own folder never matters.
- `broadsword test` has no name filter. It runs the whole suite and prints one `test <name> ... ok` line per test, then `test: ok - N passed, 0 failed` (format as in `docs/nodes/1.1.md` section 1, read from `crates/broadsword/src/` at the first brief). A check that needs one test looks for that test's own line.
- `python -I scripts/node_check.py 2.4 --list` lists these blocks and `--run <id>` runs one. It judges three rule forms only: `last line == X`, `contains X` and `exit != 0` (`scripts/node_check.py` header). Every other `PASS:` text, including every `(human)` rule, is printed as "judge by hand". Never use `--run --all` on this node: run one id at a time, and leave the `(human)` ids (d10) to Lazlo.
- A negative control (a check that must fail on purpose, d2 and d8) is written as `PASS: exit != 0`. The form alone would also pass if the example failed to build, so a negative control counts only when its positive twin (d1 for d2, d7 for d8) has passed with the same example.
- Timing checks are marked **(quiet board)** in the prose before the block. Run them only while no build, test or review is running (`broadsword status`), and rerun, never average over a busy board. Checks marked **(human)** need Lazlo and his hardware; an agent never runs them as passed.
- Anything not PASS is FAIL, including a check that cannot run because a flag, file, example or test is missing.

### Done-when line 1: 1M instances update at 60 fps

The budget is the requirement itself. 60 fps means one frame in 1/60 s = 16.667 ms = **16667 us** (arithmetic, not a benchmark). What is timed is the **CPU update** of every instance's transform for one frame, not drawing. Drawing is node 2.5, and its GPU cost is not in this check (section 4).

**d1 One million instances update within one 60 fps frame, p99.** The example creates 1000000 instances, runs 600 frames of the update, times each frame, and requires the 99th percentile frame to be at most the budget. It also checks the final transforms against a second, independent scalar implementation (a checksum), so a fast wrong update cannot pass.

```check d1
build/bin/broadsword.exe run scene -- cargo run --offline --release --example instances_bench -- --instances 1000000 --frames 600 --budget-us 16667 > scratch/n24-d1.txt 2>&1
PASS: contains instances_bench: ok instances=1000000
```

(quiet board.) The program prints `instances_bench: ok instances=1000000 frames=600 p99_us=<n> budget_us=16667 checksum=<hex>` and exits 0 only if the p99 frame is within budget and the checksum matches. Otherwise it prints `instances_bench: FAIL budget` or `instances_bench: FAIL checksum` and exits 1. Source of the budget: arithmetic above. There is no placeholder to replace: unlike node 1.1's d3, the number is the requirement. A stricter sub-budget, if Lazlo wants one, is a new decision and is recorded here with its measurement.

**d2 The benchmark can fail.** The same example with a budget no frame can meet.

```check d2
build/bin/broadsword.exe run scene -- cargo run --offline --release --example instances_bench -- --instances 1000000 --frames 600 --budget-us 1 > scratch/n24-d2.txt 2>&1
PASS: exit != 0
```

(quiet board.) Expected: the run exits non-zero (`run: FAILED (exit 1)`) and the saved file contains `instances_bench: FAIL budget` (read it by hand; `node_check.py` judges only the exit code). Reason for 1 us: one million 48-byte transform writes cannot finish in 1 us on any CPU (estimate: each write is a memory access; the whole frame is far longer). FAIL: `instances_bench: ok` (the budget check cannot fail, so d1 proves nothing).

**d3 The instance update is correct on a small scene, every value.** A test sets up 1000 instances with known transforms and rotation speeds, runs the update for 10 frames, and compares every matrix element with a reference computed in the test by a plain loop. Tolerance is exact equality for values computed the same way; the test documents the one order of operations it uses.

```check d3
build/bin/broadsword.exe test scene > scratch/n24-d3.txt 2>&1
PASS: contains test instances_update_matches_reference ... ok
```

FAIL: the line is missing (no such test) or says FAILED.

### Done-when line 2: glTF and USD files import and export round-trip

**d4 Hierarchy transforms compose correctly.** A parent-child tree with translation, rotation and scale at each node: every world matrix equals the product of the local matrices from the root, compared element by element with a reference product computed in the test. Also a cycle in the parent links is a named error.

```check d4
build/bin/broadsword.exe test scene > scratch/n24-d4.txt 2>&1
PASS: contains test hierarchy_world_matrices_match_reference ... ok
```

**d5 Layers hide and show instances (supporting; the Build line names layered scenes).** A scene with three layers: hiding one removes exactly its instances from the visible list, and showing it again restores them in the same order.

```check d5
build/bin/broadsword.exe test scene > scratch/n24-d5.txt 2>&1
PASS: contains test layer_visibility_filters_instances ... ok

**d6 glTF fixtures round-trip (import, export, import again, equal).** Each hand-written fixture in `tests/fixtures/gltf/` is imported to a scene, exported to glTF, and imported again. ```check d6

PASS: contains test gltf_round_trip_fixtures ... ok
```

**d7 The glTF example runs on a fixture (positive twin of d8).** It imports `tests/fixtures/gltf/hierarchy.gltf`, writes `scratch/n24-d7.gltf`, and prints the node count it read and wrote.

## 1. Done checks as commands

Proposed implementation checks, not checks run for this documentation task.
Use STAGE6's numbered command/evidence/PASS convention; no STAGE6.md is
present here, so reconcile its current version when the node starts.
Run from the Broadsword root after registering proposed project `path-tracer`.
Every node-specific test below is created by P1-P10 in section 7.
The existing runner captures separate files below
`scratch/node-checks/3.5/`; do not add redirects that hide its captured output.
Execute blocks through `scripts/node_check.py`, with its finite timeout
passed explicitly through `--timeout` from a required
`done_check_timeout_seconds` orchestration setting (a new key is needed if
absent; adding it is outside this documentation claim).
No unbounded manual execution. These root commands judge registered project
trees; task checks must instead insert `--task <id>` after the project name
in a separately recorded command and verify the source revision being judged.

All checks require zero exit, nonempty labelled measurements, complete case
inventories and no skipped tests. Missing references, timeouts, invalid or
non-finite pixels, empty masks, partial artifacts and unavailable GPU are
failures. A test-name match alone is not evidence unless its assertions cover
the inventory. No timing acceptance target is proposed: **no quiet-board
check**. Any future speed claim needs a separate quiet-board brief.

Acceptance budgets below are **draft engineering proposals for Lazlo**,
not published Cornell tolerances. P2 makes paths, budgets, image dimensions,
sample schedules, seeds, ray-depth/roulette policy, numeric input bands,
memory/work limits and timeouts required settings in the workload
`broadsword.toml`. Missing or ignored settings fail. P3 freezes approved
values before viewing candidate output; failed renders cannot tune budgets.

For Cornell, compare unclipped scene-linear RGB radiance at identical camera,
geometry, illuminant and exposure, before denoising or tone mapping.
Use relative RMSE = sqrt(mean squared channel error) divided by reference
RGB RMS over the complete image, with a strictly positive denominator.
Proposed final bound `0.05` allows initial Monte Carlo noise without hiding
gross illumination errors. Across independent seed ensembles, the final
sample budget must reduce aggregate squared error to at most `0.5` of the
initial budget's error; P3 chooses sufficiently separated budgets and enough
seeds to resolve that decrease. This is evidence of convergence, not a
requirement that every noisy pixel or every intermediate seed improves.
Reference uncertainty must be at most `0.01` relative RMSE, a deliberately
smaller allowance than candidate error, established by independent reference
runs, not by comparing this implementation with itself.

For material parity, compare linear diffuse/rough-metal swatch interiors
under matched direct lighting and an approved shared environment:
relative RMSE at most `0.05`, with an absolute RGB RMSE bound `0.01` for
near-black swatches whose reference RMS is below `0.01`. These proposed
budgets allow raster sampling differences, not different BRDFs. Explicit
near-black handling prevents division by zero. P3 documents masks,
colorimetry, unit radiance normalization and the reason for each exclusion;
no highlights or difficult pixels may be removed retrospectively.

## 2. Home

Proposal: separate registered repo `path-tracer`, one Rust crate
`path-tracer`; CPU-first headless integrator with a later optional GPU backend.
Under accepted `docs/adr/0001-shared-core.md` option (a), file formats are the
contract. **No Cargo dependency (path or git) on another repo without a new
ADR accepted by Lazlo. Never plan a link into `projects/foundation`.**
No patch table or sibling source import may bypass this rule.

Share materials semantically through versioned scene/material files and
cross-renderer fixtures, not an unapproved Rust import. The required schema
specifies linear color spaces, units, tangent frames, roughness mapping,
metallic/dielectric conventions, normal maps and supported extensions.
Unsupported features produce named errors, not silently different materials.
If “shared materials” requires shared executable BSDF code, stop for a new
ADR: ADR 0001 trigger 2 (“A third Rust project needs the same Vec3 or the same
parser”) is likely, and trigger 4 applies if a numerics core is reused across
projects. Lazlo decides the ADR 0002/workspace route before implementation.
`docs/adr/0004-roadmap-repo-map.md` is a proposed alternative placement,
not authority to override accepted ADR 0001. P1 must resolve placement first.

## 4. External needs

Each non-std need is a **decision for Lazlo**, before adding it:

- Rust TOML parsing and image I/O crates (candidate `toml`, `exr`); exact
  versions, transitive licences, lockfile and vendored offline sources must
  be vetted. No version selection or download occurs here. Prefer simple
  owned fixture encodings until the decision is made.
- CPU denoising initially uses local edge-aware code. Optional learned or
  third-party denoisers need a separate decision for weights and licences.
  Intel Open Image Denoise would be a C/C++ exception needing Lazlo's
  explicit approval, not an assumed dependency.
- Real-time captures need 2.5's approved GPU stack and an available compatible
  adapter. No GPU is required for CPU BVH/integrator tests. Graphics-heavy:
  the PC shares system/GPU memory; Lazlo moves this workload first and
  approves memory budgets before scheduling it.
- No tablet, gamepad, audio interface or second PC is required. A calibrated
  display is desirable for the human comparison; quantitative linear-image
  checks do not depend on it.
- Cornell/PBRT reference acquisition, renderer binaries and reference image
  generation need network/licence approval, then offline hashed storage.
  No network is permitted in acceptance runs.

## 5. Test harness

P1 creates a headless Rust library/test skeleton. P2 validates settings once
at library entry points; integrator, BVH and example use those constructors.
Bound bytes, triangles, pixels, samples, ray depth and arithmetic products
before allocation; reject NaN/inf, zero directions, degenerate geometry,
unsupported material fields, duplicates and malformed records. Test empty,
huge, negative, overflowing, subnormal and near-cancelling inputs, CR/line
breaks, Windows drive/backslash paths and traversal. Artifact paths must
remain relative to configured scratch; hostile links and partial writes
must fail without publishing a successful manifest.

P3 creates immutable fixture inventory and independent expectations:
analytic diffuse furnace and hemisphere integrals, higher-precision
intersection cases, tiny occlusion scenes, Cornell diffuse and glossy scenes,
constant/noisy-edge denoiser images, and direct/IBL material swatches.
Numeric bands are approved before arithmetic code; include smallest/largest
valid values and cancellation tests against independent high-precision
calculations, not the implementation under test. Document error derivations.

P4 uses deterministic randomized/property rays plus adversarial grazing,
parallel, inside-box, negative-scale and overlapping primitive cases.
P5-P6 compare BSDF/PDF values and integrals with independent quadrature;
zero-probability events, delta lobes and roulette termination are explicit.
P7 uses fixed seed ensembles and a frozen independent PBRT reference, not
goldens regenerated by the candidate. P8 sees only noisy radiance and
auxiliary normal/albedo buffers, never expected images at runtime.
P9 captures real renderer output; P10 tests manifest round trips, version
rejection and complete artifact inventories before granting parity.

Behavioural negative controls belong in their owning tests: disable a BVH
child and detect a missing hit; bias a PDF and detect integral/mean error;
remove indirect lighting and fail Cornell error; swap roughness and fail
parity; replace denoising with identity and fail strict improvement.
Exercise these as temporary mutations, restore them and re-read the diff.
Output labelled measurements and case counts; no empty success. Record the
exact source revisions/configuration tested, fixture hashes, adapter and
capture provenance. Tests of a commit must execute that pinned tree.

## 8. Risks and size

The biggest risks are an unresolved repo/workspace decision, unfinished
2.4/2.5 contracts, RGB/spectral Cornell mismatch, reference licensing,
reference uncertainty, mismatched tone mapping or environment lighting,
rare high-energy paths, denoising bias, and shared RAM/GPU pressure.
Freeze a common RGB model rather than claim agreement with a photograph.
Material consistency does not promise pixel identity for effects the
real-time renderer approximates; unsupported comparisons must be explicitly
scoped before testing, never excluded after failure.

Estimated implementation size: roughly 15-25 small briefs, not a measured
count. The first briefs above establish interfaces; a robust integrator,
scene reader, reference acquisition, BRDF texture support and capture
adapter will likely need further separately claimed slices. GPU tracing,
animation and performance targets are not needed for this node's stated
Done-when. BVH, importance sampling, shared PBR semantics and denoising
remain required even though raw Cornell convergence alone would not prove
all of them.

Close only when **the Cornell box converges to the reference image; the
same material looks consistent in the real-time renderer and the path
tracer**, supported by all mechanical checks and Lazlo's explicit verdict.
Nothing in this plan changes the roadmap status or declares that verdict.

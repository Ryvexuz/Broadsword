## 1. Done checks as commands

Proposed implementation checks, not checks run for this documentation task.
Use STAGE6's numbered command/output/PASS convention; `docs/STAGE6.md`
is absent here, so reconcile its current wording when the node starts.
Run from the Broadsword root after S1 registers `sculpt`. Existing runner,
Cargo flags and redirection are infrastructure; S1-S10 below create all
node-specific tests, examples, settings and output contracts.

Run each block using `scripts/node_check.py` with its `--timeout` supplied
explicitly from required `done_check_timeout_seconds` in the orchestration
`broadsword.toml` (S1). Do not run an unbounded shell block. The runner
captures output under `scratch/node-checks/3.7/`; redirects name separate
supervised-run logs. In task worktrees insert `--task <id>` after `sculpt`.
Never nest a Broadsword job or run Cargo directly.

All checks require exit zero, nonempty case inventories and labelled
measurements. Missing, skipped, ignored, truncated or non-finite results,
timeouts and partial artifacts fail. Sentinels are emitted only after
internal assertions succeed. Automatic success cannot approve a human check.

Acceptance budgets below are **proposals for Lazlo**, not published results.
S2 makes limits, paths, tolerances, seeds, sample counts, warm-up duration,
stroke duration, timeout and memory budget required settings in the sculpt
repo's `broadsword.toml`. S3 freezes their approved values before testing.
The face count is 5,000,000 from the roadmap, interpreted as active,
editable triangles, not hidden base faces or a proxy. Dynamic topology may
change that count during a stroke: benchmark subdivision and collapse
separately, starting each replay at the target count, reporting all counts.

Proposed interactive budgets: p95 presented-frame interval at most 33 ms
and p95 input-to-present latency at most 50 ms, with no interval above
100 ms during the measured stroke. These are engineering choices for
roughly fluid direct manipulation with a stall bound, not Blender claims.
S3 specifies percentile ranking, clocks, warm-up, sample inventory and
measurement overhead. Test the actual edited mesh with normal updates,
upload, drawing, presentation and undo capture enabled. Include orbiting,
ordinary brushes, dynamic topology and multires level changes as separate
cases; no averages hiding a slow mode. Memory must stay within Lazlo's
machine-specific approved shared RAM/GPU budget, with no allocation failure.

## 2. Home

Proposed separate repo `projects/sculpt`, Rust library crate `sculpt`, with
local viewer and benchmark examples. Lazlo approves creation/registration
in S1; this task creates no repo. Under accepted
`docs/adr/0001-shared-core.md`, option (a), file formats are the contract.
No Cargo dependency (path or git) on another repo without a new ADR
accepted by Lazlo; never a link into `projects/foundation`.

Reuse node 2.2 (`brush-engine`) through a versioned exported dab stream
generated by its real engine, with a producer-side export brief if missing.
Reuse node 2.3 (`mesh-kernel`) through versioned mesh snapshots including
attributes and subdivision metadata. The sculpt-specific mutable working
mesh lives locally; serialization is not a per-frame cross-process mesh copy.
If interactive engine calls or kernel internals are needed rather than
files, stop for ADR 0001's (d2)/ADR 0002 workspace decision, Lazlo's call.
In particular trigger 2, “A third Rust project needs the same Vec3 or the
same parser”, needs review before S1; do not silently copy a shared core
to evade it. Common numerical machinery also requires trigger 4 review
if needed by two projects. No cross-repo library import is presumed here.

## 4. External needs

This is **graphics-heavy**: system RAM and GPU share memory on Lazlo's PC;
Lazlo moves/schedules it first, before full-size allocation or timing.
GPU access, a display with presentation timing support, and Lazlo's
pressure tablet are needed for acceptance. No gamepad, audio interface,
second PC or network dataset is required. Headless tests do not prove
interactive presentation.

Each non-std need is Lazlo's decision: proposed Rust `wgpu` for drawing and
GPU timestamps, `winit` for window/input, and a tablet backend selected
after testing the actual device. Vet, pin exact versions, review licences
and transitive native components, then vendor for offline builds. No crate
is approved or fetched here. Prefer std-only format parsing, fixtures and
CPU edits initially. A C/C++ tablet or graphics library is an exception
requiring Lazlo's approval, not an assumed fallback. S1 records the final
dependency/licence inventory; unavailable timing support blocks s5 rather
than silently replacing presentation timing with CPU submission time.

## 5. Test harness

S3 supplies generated plane, boundary patch, tetrahedral closed surface,
subdivision patch and target-size triangulated surface recipes, plus dab
traces with pressure changes, pauses and edge hits. Large meshes are
generated in scratch, not committed as binaries. Record generator version,
seed, actual counts and hashes. Independently authored expected coordinates
and weights must not come from sculpt's own output.

Map s1 to inventory/settings tests; s2 to direct library invalid-input and
failure-injection tests; s3 to producer golden streams plus analytic plane
displacements; s4 to rational subdivision references, mesh invariants,
round trips and bounded property tests; s5 to quiet-board presented-frame
benchmarks; s6 to a human session with the same workload manifest.
Golden streams include producer revision and schema version, not merely a
filename. Contract drift must fail visibly.

Validation covers negative/empty/overflow counts, NaN/inf, subnormal and
extreme coordinates, near-cancelling normals, zero pressure, bad indices,
duplicate fields, truncated records, CR/line breaks and Windows drive,
backslash and traversal paths. Bound work/allocation before parsing and
editing; reject unsupported ranges with named errors in one constructor.
Check finiteness immediately before publishing edits. Inject allocation,
upload and mid-edit failures: no partially committed mesh or undo entry.
Test link replacement for artifact destinations; fail closed rather than
following outside scratch. Keep first errors visible.

Freeze a documented numeric range and tolerance rule in S3, then test its
extremes against independent rational or higher-precision references.
Topology/count/schema checks and canonical undo bytes are exact; coordinate
checks use the approved scale-aware error budget, not unexplained literals.
For each guard, describe a behavioral mutation: bypassing face-count
validation must accept an invalid fixture and fail s2; disabling detail
transfer must lose the known displacement and fail s4; deliberately delaying
a presented frame must fail s5's stall test. Include a synthetic over-budget
timing log to prove the benchmark judge fails, without requiring a slow PC.

## 8. Risks and size

Main risks: ADR-triggered architecture change; missing producer contracts;
detail loss at topology/level boundaries; latency hidden by GPU queues;
tablet timestamps on different clocks; shared-memory exhaustion; and
dynamic topology work proportional to the whole mesh rather than the
edited region. Full-size interactive validation must precede polish, not
be inferred from small CPU tests.

Rough planning estimate: ten seed briefs listed above, followed by additional
briefs for integration, acceleration, platform work and profiling as measured.
This is not a promise that a complete sculpt editor fits those seeds.
Do not declare the node done until the verdict is exactly: **a 5M-polygon
sculpt stays interactive**, supported by s1-s6 and Lazlo's recorded approval.
Open decisions carried forward: home/ADR, producer exports, dependency and
data licences, tablet backend, timing instrumentation, numeric range,
machine-specific budgets and quiet-board scheduling.

## 1. Done checks as commands

These are **future commands**, not commands runnable in this documentation task.
Numbered command/PASS checks follow the requested STAGE6 style; `STAGE6.md` is
not present in this worktree. The actual fence and rule syntax follows
`scripts/node_check.py`, the local implementation of the ra-node-check contract.
Each fence has its command first and its `PASS:` rule next.

Run from the Broadsword root, in the foreground, after section 7 is implemented.
`broadsword` denotes the installed tool resolved from the configured `install_dir`.
The project is `audio-device`; in a task add `--task <id>` after that name.
The outer runner must give **every** command a process-tree timeout: use
`scripts/node_check.py` with its existing `--timeout` option, supplying the
appropriate required timeout value from the workload's `broadsword.toml` described
below. Do not use its default for the soak. Do not invoke node_check inside a
Broadsword job: its nested-job guard forbids that. Build and test only through
Broadsword; the cargo commands below are children of `broadsword run`.

The redirections name separate scratch outputs for direct shell execution.
Node_check strips those redirections and instead saves its captured output under
`scratch/node-checks/1.10/`; do not expect both copies. A check requires exit 0
and its labelled evidence, not merely absence of an error. Empty output, a missing
test, device or fixture, timeout, panic, refused configuration, incomplete capture,
or truncated evidence is a failure, never a skip. Unit checks run the complete
suite because `broadsword test` has no test-name filter. Only the named test's
`... ok` line satisfies its check.

**Settings, not constants.** A1 creates `broadsword.toml` at the **new workload
repo's root**, separate from the platform's file of the same name. A4 reads its
required `audio_device_*` keys; no platform parser or CLI changes are assumed.
The executable reads this file relative to its project working directory, so
main checkouts and task worktrees use the same command without depth-dependent
`../../` paths. It prints the validated settings and their source. All tunable
limits and paths belong there, including the fixture directory, sample rate,
channels, sample format, buffer frames, input/output endpoint IDs, backend,
probe seed and level, warm-up, minimum probes, measurement duration, drift band,
correlation/ambiguity thresholds, telemetry capacities, capture byte cap,
quiet-board CPU ceiling, deadlines and shutdown grace. Missing keys are errors.
Do not select the default audio device silently.

The settings file itself must also be bounded before TOML parsing. A1's build
stamp embeds the required `audio_device_settings_max_bytes` from the reviewed
repository profile; A4 uses that trusted bootstrap cap before reading a runtime
copy. An input file cannot raise its own read cap; raising this bootstrap setting
requires a rebuild. Test an oversized config as well as oversized evidence.

Required acceptance keys include `audio_device_round_trip_limit_ns`,
`audio_device_soak_seconds`, `audio_device_allowed_dropouts`,
`audio_device_test_timeout_seconds`, `audio_device_latency_timeout_seconds` and
`audio_device_soak_timeout_seconds`. The acceptance profile must keep the roadmap's
strict **under 10 ms**, **at least one hour**, and **zero** rules. Changing a
setting cannot relax that contract: A4 rejects a weaker profile, and A9 consumes
only that validated profile. The soak timeout
must exceed warm-up plus measurement plus bounded shutdown and compilation
allowance; otherwise fail configuration before opening devices. The ordinary
queue's shorter `done_check_timeout_seconds` is not the soak route.

**Measurement definition.** Physical output-to-input electrical loopback on one
full-duplex interface measures the combined output path, D/A, cable, A/D and
input path, including application buffering. Never substitute an OS software
loopback, a reported driver latency, callback execution time, or half of a
one-way estimate. Use a continuous, known sequence and uniquely identified probe
slots; record render/capture sample positions and monotonic timestamps. A5/A10
must establish the mapping between the two timelines and its uncertainty.
For each valid probe, compare its conservative latency upper bound (measured
delay plus alignment/clock uncertainty) to the limit; **every bound**, not its
mean or percentile, must be below the limit. Missing/ambiguous probes fail.
Uncertainty is never subtracted to obtain a pass.

**Dropout definition.** Count driver-reported underruns/overruns/discontinuities,
application ring underflow/overflow, missing/duplicated/reordered probe slots,
unexplained sample-position or timestamp gaps, device loss and stream resets.
Report each class separately, with their union as affected events; overlapping
classes do not cancel. A reset or disconnect ends the run as a failure rather
than restarting its clock. Monitor continuously from stream start, report warm-up
separately, and require one uninterrupted measured interval after warm-up.
An error callback alone is not proof of zero dropouts. Backend telemetry and
continuous captured-signal monitoring must cover the whole measured interval.
Unknown coverage or an unavailable required counter is `UnsupportedTelemetry`,
not a zero counter. Analogue detection sensitivity and clock-drift treatment must
be qualified in A10 before the zero-dropout result can be accepted.

```check a4

PASS: contains test continuity_rejects_injected_faults ... ok
```

duplicating a frame, losing a probe, ring overflow, timestamp regression, reported

```check a5

PASS: contains test verdict_rejects_incomplete_or_nonfinite ... ok
```

A9 creates this test. A complete known-good record passes; an empty/partial,
stale-run, wrong-profile, uncalibrated, missing-counter, lost-telemetry or

6. **Physical round-trip latency (Lazlo setup; quiet board, timing).**

```check a6
broadsword run audio-device -- cargo run --offline --release --example devicecheck -- --case latency > scratch/n110-a6.txt 2>&1
PASS: contains latency: PASS all_probe_upper_bounds_lt_limit
```

A2 creates the example and `--case` flag; A10 implements `latency`. Output must
label backend/device/driver, negotiated format and buffer sizes, profile and run
IDs, board state, probe count, minimum/median/maximum measured delay, maximum
uncertainty and maximum upper bound, with units. Zero probes cannot pass.
The threshold is the roadmap's under 10 ms, not a published device benchmark.
Probe count, level, warm-up and observation duration are **unverified calibration
choices for Lazlo**, recorded in settings before running, not hidden constants.

7. **Uninterrupted soak at the same low-latency profile (Lazlo setup; quiet board).**

```check a7
broadsword run audio-device -- cargo run --offline --release --example devicecheck -- --case soak > scratch/n110-a7.txt 2>&1
PASS: contains soak: PASS uninterrupted_duration_met dropouts=0 latency_gate=PASS
```

A10 implements `soak`. Output includes actual monotonic measured duration,
expected/observed frame and probe counts, all dropout counters, telemetry losses,
coverage, drift and the latency upper-bound summary throughout the interval.
The duration and zero threshold come directly from the roadmap. Keep latency
monitoring enabled throughout: do not pass latency with a small buffer and then
soak with a larger buffer. Checks a6 and a7 must identify the same interface, backend,
driver, format and buffer profile; any change requires both to run again.

8. **Qualification of fault detection (automated negative controls).**

```check a8
broadsword run audio-device -- cargo run --offline --release --example devicecheck -- --case negative-controls > scratch/n110-a8.txt 2>&1
PASS: contains negative-controls: PASS clean_accepted faults_rejected
```

A10 implements this fixture-only mode. It passes only when the clean independent
fixture is accepted and each declared corruption is rejected with its expected
reason. Include a delayed probe that reaches the latency limit and a truncated
soak that retains a forged success footer. Injection cannot be enabled in a live
qualification session. Disabling the continuity guard would yield
`negative-controls: FAIL fault_accepted`, rather than just a compile failure.

9. **Wiring, calibration and evidence acceptance (human: Lazlo).**

```check a9
broadsword run audio-device -- cargo run --offline --release --example devicecheck -- --case inspect > scratch/n110-a9.txt 2>&1
PASS: (human) Lazlo confirms physical electrical loopback, safe levels, calibrated sensitivity, quiet-board records and matching a6/a7 profiles; both a6 and a7 must already PASS.
```

A10 implements `inspect`, displaying the validated summaries and calibration
record, failing if either is missing. Lazlo confirms that hardware direct
monitoring, software loopback, effects, AGC and sample-rate conversion have not
provided an unintended shorter path. Disconnect speakers/headphones before
probing; never connect an amplified speaker output to a line input. No agent
opens a microphone or emits a test signal without his approval. The parser
reports this free-text rule as "judge by hand"; it cannot grant a human PASS.

Quiet-board evidence is required for a6/a7, not inferred from fast execution.
A10 records board status at start/end and samples load through the measurement;
Lazlo reserves the interface and pauses builds, tests, reviews and unrelated
audio. The required CPU ceiling and sampling interval are provisional settings
approved during calibration, with the reason recorded; excess load invalidates
qualification and requires a fresh run. Preserve failures, never average them
away. Archive accepted summaries, raw evidence and human sign-off into a later
explicitly claimed evidence file before scratch cleanup. Neither tests alone
nor a software loopback can satisfy the Done-when.

## 2. Home

Proposed new separate repo **`projects/audio-device`**, package/library
**`audio-device`** (`audio_device` in Rust), with the `devicecheck` example. A1 is
future approved repo setup, not permission to create it during this task. It
remains outside the Broadsword Cargo workspace and uses the configured shared
build directory. It is a headless platform service, not a DAW or mixer.

Follow **Accepted ADR 0001, option (a)** (`docs/adr/0001-shared-core.md`):
separate repos; file formats are the cross-repo contract. This repo owns a small,
versioned capture/measurement format and its frozen fixtures, so future consumers
can validate copies without importing a library. No Cargo `path` or `git`
dependency on another repo, no links, no `[patch]` workaround, no building against
another repo's uncommitted tree, and **never a link into `projects/foundation`**.
The node needs no foundation source to implement its dedicated audio callback;
0.4 remains a prerequisite, not an implicit dependency exemption.

Live reuse of 0.4's scheduler, or hosting this audio layer in a different repo's
in-process DSP/editor, is **not planned as a cross-repo dependency**. If required,
stop for Lazlo's new ADR. ADR 0004's proposed **T6** (live shared-core product
intent) is the relevant additional trigger; it is not an accepted ADR 0001
trigger today. ADR 0001 trigger **2** applies if a third Rust project needs the
same parser, and trigger **3** if a duplicated core bug is fixed in one copy but
not the other. These are review points, not permission to invent a path
dependency. Accepted ADR 0001 calls for the (d2) route via a new ADR when its
triggers fire. Proposed ADR 0004 maps 1.10 to **W/media-io**; revise this home and
all claims only after Lazlo accepts a migration. Do not silently treat that
proposal as already applied.

path. The real backend must never fall back to offline fixtures. A1 defines the
small module interfaces and documented non-operational stubs; a missing
implementation returns an explicit error, never successful silence. A2 makes
the command harness fail closed until its required implementations exist.

Fixtures (A3): `tests/fixtures/probe_v1.csv`,
`tests/fixtures/latency_reference_v1.csv`,
`tests/fixtures/continuity_v1.csv`, with provenance and construction in
`docs/FIXTURES.md`. These are small original text fixtures, not downloaded music
or golden output generated by the implementation under test. Property tests
derive expected sample delays independently using checked rational arithmetic.
Numeric tests cover the constructor's minimum/maximum valid rates, durations,
positions and capacities, subnormal/non-finite probe levels, near-tied peaks and
worst-case intermediate products. Bound signal amplitudes and analysis windows
at construction, document the valid band, and check finiteness on values about
to reach the device before changing stream state. Invalid values get named
errors; do not clamp them to silence or zero.

The versioned record contract (A1/A9, documented in `docs/FORMAT.md`) includes
schema/run/profile IDs, source revision and dirty state, backend/driver/device,
negotiated format, monotonic interval bounds, sample positions, probes and their
uncertainties, counters and evidence coverage. A10 records the actual tree under
test and the binary's embedded source ID; do not measure whichever executable
was last left in the shared target folder. Hardware results are tied to this
tree/profile, not to another commit's diff.

All evidence paths come from settings and stay within the configured scratch
root. Create new run-specific files without overwriting old failures; reject
links/reparse points and use handle-based checks so a link swapped after a path
check cannot redirect writes. No recursive cleanup or subprocess launched by
devicecheck is needed. The outer timeout owns the complete Broadsword process
tree; the session itself has bounded stream stop and evidence flush. A failed
flush or stop preserves the first error and marks retained data incomplete.

A7's device reservation is keyed by resolved endpoint identities, not project or
profile names. Use OS locks/owned handles, acquire endpoint pairs in stable order,
and never take over a supposedly stale lock. Its tests must include two aliases
for the same endpoint and failure after reserving only one endpoint: the second
session fails closed, and partial ownership is released safely.

Mutation proof, in future explicitly claimed test code only: disable the latency
comparison and a2 must report acceptance of the equal-limit case; disable the
continuity guard and a4/a8 must report an accepted missing frame; remove footer
validation and a5 must reject the resulting false pass. Restore every mutation
and re-read the diff. No mutation is performed in this documentation task.

## 8. Risks and size

- **Home/prerequisite decisions are open.** 0.4 is not yet complete per the local
  roadmap. ADRs 0003/0004 are Proposed. Do not turn a planning file into approval
  for dependencies, native libraries, migration or bypassing prerequisite gates.
- **Telemetry is the main feasibility risk.** CPAL may not expose enough
  information to prove zero dropouts or a common render/capture timebase on the
  chosen backend. A7 must stop with `UnsupportedTelemetry` if so. A native Windows
  adapter and an additional dependency/exception may be needed; that requires
  Lazlo and new briefs, not a fabricated zero.
- **Hardware might miss the budget.** Built-in/shared-mode audio, driver safety
  buffers, power management or independent input/output clocks may prevent under
  10 ms. Report actual bounds and configuration. Never change the strict gate,
  subtract cable/converter delay or expand buffers only for the soak.
- **Analogue continuity is not bit equality.** Noise, gain and drift make exact
  sample matching invalid. Calibration must establish the minimum detectable
  fault and false-positive band; digital single-frame fixture success alone
  does not prove detection of a one-frame analogue loss. If the accepted dropout
  definition cannot be observed, report that gap and revise before declaring
  Done-when met, rather than weakening the definition silently.
- **Real-time safety and test realism.** Allocation counters and adapter fakes
  cannot certify OS scheduling; physical runs are mandatory. Callback code,
  shutdown races and output-path protections merit independent high-risk review.
  Missing/midway evidence and load excursions fail closed without deleting data.
- **Soak logistics.** Reserving one uninterrupted quiet-board hour can conflict
  with the main project and normal queue timeouts. Arrange a foreground,
  process-tree-bounded manual qualification window; yield priority before
  starting, not by pausing and resuming a passing soak clock.
- **Privacy/disk limits.** Probe-only capture and bounded streaming evidence
  reduce privacy/disk exposure, but a full interval must remain auditable. A byte
  cap cannot discard unchecked data or erase a failing interval to preserve PASS.
- **Integration is later.** File evidence does not provide live in-process DSP,
  a DAW, resampling, Bluetooth qualification or portable backend parity. A future
  consumer or shared scheduler requirement reopens the ADR and home decisions.

**Size estimate:** A1–A10 are the initial brief set; allow additional tightly
claimed adapter/fix-round briefs if the capability spike or calibration fails.
The rough delivery estimate is **10–14 briefs**, not a measured line or timing
total. Size calculation (PowerShell, documentation arithmetic only):
`"initial={0}; reserve={1}..{2}; total={3}..{4}" -f 10,0,4,(10+0),(10+4)`
prints `initial=10; reserve=0..4; total=10..14`. Setup/harness/fixtures precede
the production path, and hardware evidence plus Lazlo's sign-off is still needed
after the code briefs; merged code alone is not node completion.

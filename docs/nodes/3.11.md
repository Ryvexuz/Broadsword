## 1. Done checks as commands

These are future implementation checks, not results of this documentation
task. Use the numbered command/PASS convention of the other `docs/nodes/*.md`
plans (there is no `docs/STAGE6.md`).
Run from the Broadsword root after registering proposed project
`parametric-cad`. Section 7 creates every workload test target below.
`cargo` appears only behind `broadsword run`, never as a direct build route.

Run each block as `python -I scripts/node_check.py 3.11 --run <id>` (add
`--root <worktree>` to judge a task tree). The runner already bounds every
command with `--timeout` (default 3600 s, killing the whole process tree); a
different bound is passed on that command line, and no new setting is needed.
It captures output in `scratch/node-checks/3.11/<id>.txt`; each check has its
own filename. The runner refuses to run inside a Broadsword job, so never nest
one. For task evidence record the exact command including `--root` and the
source revision, rather than attributing a main-tree run to a task commit.

All checks require exit zero, no ignored cases and nonempty labelled output.
F2/F3 define case inventories; missing fixtures, unsupported workers,
timeouts, non-finite measurements and partial results fail closed.
Tests print source revision, fixture revision, settings and worker identity.
The orchestrator pins the tree to the commit being judged; a printed SHA
alone does not establish that the correct tree ran.

**Acceptance policy, frozen before candidate runs (F2/F3).** Topological
validity, solid count, feature order, dependency identities, selected
semantic entities, command history and revision transitions are exact
checks. Geometric comparisons use `abs(actual - reference) <=
abs_budget + rel_budget * abs(reference)`, with finite operands and a
separate documented reference-error allowance. Length, area, volume and
centroid components have separate unit-aware budgets; normals use an angular
budget. F3 derives them from 3.10's documented modeling tolerance, fixture
scale and reference precision;
no numeric accuracy threshold is invented here. Lazlo approves them before
implementation acceptance; unresolved budgets block the checks, not default
to infinity. Reference uncertainty must fit inside its allocated allowance.
STEP bytes and transient kernel edge indices are not geometric oracles.

**1. Contracts, settings, fixtures and hostile inputs (F1-F5/F10).**
```check contracts
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test contracts -- --show-output --test-threads=1
PASS: contains test contracts_and_rejections ... ok
```
Require all operator kinds, both worker contracts and all fixture inventory
entries, with labelled tested/rejected counts. Test the lowest constructors
and decoder directly, not just the acceptance entry point.

**2. Dependency scheduling and stable references (F6/F8).**
```check dependencies
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test dependency -- --show-output --test-threads=1
PASS: contains test dependency_and_reference_contract ... ok
```
An edit dirties every descendant and no unrelated branch. Evaluate in a
deterministic dependency order. A semantic selection resolves uniquely after
the edit or reports an explicit missing/ambiguous-reference error; nearest
edge, first edge and numeric-index fallbacks are forbidden.

**3. One dimension regenerates the complete real part (F10).**
```check regenerate
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test regeneration -- --show-output --test-threads=1
PASS: contains test dimension_edit_regenerates_whole_part ... ok
```
Load the mixed-feature fixture, change only its named root sketch dimension,
solve through the real 2.9 worker and regenerate through the real 3.10 worker.
Both baseline and changed part must pass solid validity and frozen
intermediate/final reference comparisons. Require extrude, revolve, fillet
and chamfer to execute, and record their input/output revisions. The changed
part must differ in the independently specified observables, not just carry
a new timestamp. Compare incremental regeneration with a clean rebuild as a
secondary consistency check, never as the sole correctness oracle.

**4. Full feature history survives editing and reopening (F9/F10).**
```check history
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test history -- --show-output --test-threads=1
PASS: contains test history_roundtrip_undo_redo ... ok
```
Record each construction command and the dimension edit. Undo the dimension
edit to the exact baseline document, then all construction to the exact
empty start; redo to the exact edited document. Save/reopen and regenerate
baseline and edited endpoints against the frozen references. Preserve
feature IDs, parameters, order and selections; derived B-rep cache bytes
need not match. Test redo invalidation after a new edit, grouped rollback
and the configured history cap.

**5. Failed regeneration never publishes a partial part (F5/F9/F10).**
```check rollback
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test failure -- --show-output --test-threads=1
PASS: contains test failed_regeneration_is_atomic ... ok
```
Include invalid dimensions, an impossible fillet, lost selections, malformed
worker results, resource exhaustion and mid-write/worker failure.
The committed document, solid and undo cursor stay at the previous revision.
An attempted edit may be retained separately as a failed proposal with the
first failing feature/error; it is never labelled the regenerated part.

**6. The acceptance checker detects believable wrong results (F3/F10).**
```check oracle
build/bin/broadsword.exe run parametric-cad -- cargo test --offline --test oracle -- --show-output --test-threads=1
PASS: contains test oracle_rejects_stale_and_wrong_parts ... ok
```
Supply a geometrically valid stale baseline, wrong units, wrong but valid
solid, omitted downstream feature and empty inventory. Each must be rejected
with its named reason; an expected rejection is asserted inside this test,
not inferred from an arbitrary nonzero process exit.

**Human/timing labels.** None of these is a human or timing check.
Lazlo must decide architecture, dependencies, licences and tolerances before
acceptance. An optional later CAD-viewer inspection is a human check for
Lazlo, not a substitute for check 3. No latency or interactive-speed claim is
made; a future timing check needs its own quiet-board brief and budget.

## 2. Home

**Proposed current-policy home:** a separate repo registered as
`parametric-cad`, containing a Rust library crate `parametric-cad` with its
own workspace boundary. It is workload code, not a Broadsword platform crate.
The project location comes from the configured `projects_dir`; no literal
absolute installation path is part of the design.

`docs/adr/0001-shared-core.md` is Accepted, option (a): separate repos,
copies where appropriate, **file formats are the contract**.
There is **no Cargo dependency, path or git, on another repo**.
Never plan a link into `projects/foundation` (or a junction, symlink, hard
link, root Cargo patch or absolute-path workaround).

Use versioned, bounded request/result files to call the sketch and B-rep
workers as processes. The 3.11 library owns the feature DAG, semantic
references, regeneration transaction and persistent construction history.
2.9 owns constraint solving; 3.10 owns solid modeling and native resources.
Opaque shape files plus versioned semantic provenance cross the boundary,
not Rust pointers or another repo's source. Worker executables and their
private runtime libraries must be revision-pinned artifacts from the actual
prerequisite builds, not whichever binary happens to be on PATH.

**Missing interface, not existing capability:** neither worker protocol is
established by this plan. Before F5, separate prerequisite-owner briefs must
provide sketch parameter editing/solved profiles and B-rep operation jobs
with shape validity, measurements and semantic topology provenance.
Freeze those contracts before adapters. If the existing nodes cannot supply
them, stop and report the prerequisite gap; saved canned answers are not a
regeneration backend.

For 0.6, first consume its command/undo *semantics*: local reversible
document commands and transaction snapshots, tested against its documented
contract (`docs/nodes/0.6.md`). This is not a claim to import its `History`
implementation or serialise its existing command objects.
If using that actual implementation is required, obtain Lazlo's ADR decision
before proceeding.

**ADR triggers and alternative home:** live solver/kernel/undo reuse would
require code from the repos owning 2.9, 3.10 and 0.6. A third Rust project's
need for the same parser/math fires ADR 0001 trigger **2**; shared numerics
between solver and kernel fires trigger **4**; a shared-copy bug fires
trigger **3**. Those require the ADR 0002 / (d2) decision, not an ad hoc
dependency. ADR 0001 trigger 1 concerns the sim specifically; do not pretend
it already authorises CAD linkage. `docs/adr/0004-roadmap-repo-map.md` is
**Proposed**, mapping this node to W/cad and adding live-data trigger T6.
If Lazlo accepts that direction, rewrite this home to a CAD-group crate in
the single workload workspace and reissue claims/commands before coding.
ADR 0003 is also Proposed, not blanket dependency approval.

## 5. Test harness

| Check | Proof and fixtures to create |
| --- | --- |
| contracts | Inventory, schema/round-trip and direct constructor/decoder tests. Empty/truncated records, unknown schema/op, duplicate IDs/fields, cycles, dangling refs, oversized graphs/files, invalid encodings and trailing junk must be named errors. |
| dependencies | Small branching DAG with known dirty sets and deterministic evaluation order; independent semantic references across width edits; explicit ambiguity and deleted-face cases. Reordering kernel enumeration must not retarget a feature. |
| regenerate | Real worker integration over the mixed-feature part, both frozen dimensions and every intermediate solid; closed-form prism/cylinder controls plus independently authored mixed-part captures. All descendants must be real newly evaluated features. |
| history | Canonical document round trips, command-log replay, undo/redo endpoints, groups and redo invalidation. Known documents and frozen geometric endpoints, not candidate-generated goldens. |
| rollback | Fault injection at each transaction boundary and at worker/IO failure, checking old document/solid/cursor remain valid. Hostile dimensions and an invalid fillet must exercise actual lower-level APIs. |
| oracle | Negative controls against the same acceptance evaluator: valid stale/wrong shapes, missing cases, unit swaps and omitted features. Print expected and observed rejection reasons. |

**F3's committed, small text fixture set:**

- `tests/fixtures/prism.case` and `tests/fixtures/cylinder.case`: fully
  constrained integer/rational profiles with exact dimensions and analytic
  bounds/volume/centroid formulas. Cylinder references use independently
  bounded pi, not this implementation's computed volume.
- `tests/fixtures/mixed.case`: one part with a master sketch dimension
  driving a revolved stepped hub and an additive extruded boss, then a
  shoulder fillet and a chamfer on a different, semantically named edge.
  Keep the chosen edit inside a topology-preserving band; prove feature
  targets remain unique at both values. A separate edit intentionally loses
  a reference. No UI selection by ordinal edge number.
- `tests/fixtures/expected.tsv`: immutable baseline/edited intermediate and
  final observables, analytic controls and reference uncertainty, with units.
  Include oriented section loops and surface/normal witnesses around each
  feature, not merely volume and bounding boxes that different solids can
  share. Freeze sample locations before candidate runs and use F3's
  length/angular budgets. Assert the expected analytic surface types.
- `tests/fixtures/provenance.txt`: author, permitted licence, formula/source,
  exact tool/kernel versions, settings, capture revision and checksums.
  `tools/reference_capture.py` describes the independently authored FreeCAD
  construction, never calls 3.11 and is not run by acceptance.

Independent review must verify the fixture's dimensions, fillet/chamfer
conventions and observables *before* candidate output is viewed. FreeCAD and
3.10 may share OCCT: this is an independent history construction, **not**
an independent geometric kernel. Analytic controls address part of that
correlation; a second kernel is a later, licence-gated option.

**Numeric coverage.** F2 supplies policy; F4's constructors bound finite
positive dimensions, permitted angles, radius, feature count and accumulated
size before arithmetic; reject invalid signs and empty fields,
NaN/infinite, overflow, subnormal and underflowing inputs outside the
documented band. Kernel results must be finite, valid and within the size
band immediately before any commit. Test smallest/largest permitted and
near-cancelling valid combinations against F3's higher-precision or
interval-bounded references. Every float comparison uses the frozen
unit-aware tolerance or a deliberately exact check.

**Worker and storage safety.** F5's adapter supervises each worker process
tree, caps streams before storage, uses bounded readers and never treats
EOF as a successful result. Test huge output, a grandchild retaining pipes,
timeout, a worker crash after writing a partial result and failed cleanup.
All cause a reported failure preserving the first error and last committed
part; diagnostic truncation must be labelled. Validate result schema,
revision, lengths, units, provenance and finiteness before using results.
Never salvage a parseable prefix or a previous result after worker failure.

Use exclusively created job directories below configured scratch, no
recursive delete/move outside them, and never overwrite committed user files
to stage a proposal. Test Windows drive/UNC/backslash paths, traversal, CR
and other line breaks, junction/symlink replacement races and mid-write
errors. Enforce containment at the actual open/publish boundary or fail
closed; a preliminary canonicalisation alone is insufficient.
Concurrent jobs must not share filenames; shared artifact locks are keyed
by the resolved artifact/resource path, not project label.

**Behavioral mutation evidence.** Disable dirty propagation: regenerate
must report a stale downstream revision or geometry mismatch. Bypass unique
reference resolution: dependencies must report wrong selection/accepted
ambiguity. Publish before validation: rollback must report changed committed
state. Disable volume comparison: F3's numeric negative control, with only
volume outside its budget, must fail its expected-rejection assertion.
Run each mutation in its own future scratch/task tree, preserve the failing
output, restore the mutation and re-read the final diff. A compile failure
does not demonstrate any of these behaviors.

## 8. Risks and size

- **Architecture may move first.** ADR 0004 proposes W/cad; it is not
  accepted. Live-data reuse could make file workers the wrong long-term
  boundary. Obtain Lazlo's ADR decision and rewrite, rather than linking
  foundation or silently turning Proposed into Accepted.
- **Prerequisites are a real gate.** 3.10's current roadmap promise does
  not cover chamfer, additive operations or persistent topology provenance.
  2.9's plan does not promise a worker. Those extensions, their evidence,
  deployment and licence decisions remain open; do not report node 3.11
  done because local scheduler tests passed.
- **Topological naming is the hard domain risk.** A width edit may split or
  merge edges. Unique semantic provenance, explicit ambiguity and a declared
  topology-preserving baseline band are required. General persistent naming
  across arbitrary edits is larger work, not a nearest-edge heuristic.
- **History is more than undo.** The full feature recipe and edit log must
  survive reopening even when kernel caches are discarded. 0.6 does not
  serialize commands or guarantee application atomicity. F9 owns both gaps.
- **Reference correlation and licences.** FreeCAD/OCCT agreement is not
  independent-kernel evidence. Keep analytic controls, independent recipe
  review and declared uncertainty. Tool availability, data licensing and
  tolerance derivation are unresolved, not checked facts.
- **Safety/size pressure.** Process-tree supervision, Windows path races,
  canonical parsing and transactional publication may not fit F5/F9's
  estimates. Split them before assignment; incomplete integration remains
  blocked until the real implementation exists. No fake workers, ignored
  cases or loosened thresholds to obtain a green suite.
- **Performance is unclaimed.** File/worker overhead and large-model memory
  may later require a different architecture. Set resource limits, preserve
  failure evidence and measure on a quiet board before promising latency.

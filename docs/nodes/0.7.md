# Node 0.7: Plugin/module system

Roadmap "Done when": a module hot-reloads without restarting the app. Status: in progress.

Code and doc are in `projects/foundation` (`src/plugin.rs`, `projects/foundation/docs/plugin.md`). Merged commits: `4f4ab21` (host, versioned C ABI, hot reload, gate) and `765eb17` (tests compile their own test plugins with rustc; the gate is an exact file-name allow-list).

## What is there

- A host that loads a cdylib by path through a versioned C ABI table (version 1) and refuses another version, naming both.
- Hot reload (`HotPlugin::reload_if_changed`): the host loads a copy of the file, so the original can be rebuilt while the app runs, hands the old state to the new library as a blob and swaps; a refused or failed reload keeps the old plugin running.
- `tests/plugin.rs` builds three test plugins from `tests/plugins/` and covers load, refusal of a wrong ABI version and reload.

## Limits the doc states

- Hard gate: only the three test plugin DLL names may load, so no third-party code runs until the OS sandbox node is done and Lazlo approves. The gate checks the name, not the bytes.
- Windows only: other platforms get a stub returning `Unsupported`, and the doc says it was not compiled on Linux.

## What is left

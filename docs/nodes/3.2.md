# Node 3.2 Soft body and deformables: infrastructure plan and done checks

**Status: draft: rewrite when the node starts.** Planning only; no code, downloads, repo creation or check execution in this task.

Source of scope: `CAPABILITY_ROADMAP.md`, Part 5, node 3.2: node-beam/FEM soft bodies, cloth, plastic deformation and breakage (BeamNG-style vehicle physics). Needs: 3.1, 2.3. **Done when: in the car crash simulator, a car hits a wall and deforms plausibly in real time.** `ROADMAP.md` row 3.2 maps this to Stage 6 and says `in progress`, citing crash-sim's solver. That evidence is not evidence that the whole capability is finished.

The brief adds the required end state: deformation and separation driven by internal structures, not just a deforming skin. Front rails, crush cans, bumper beam, A/B pillars, sills, floor, firewall, spot welds and bolted joints are in scope. The first milestone retains the lighter node-beam car; subsequent milestones add section/material-bearing members, then failing joints, then the complete structural car. Passing the lighter-car checks must never be recorded as completion of that end state.

This is lowest-priority ahead work: prerequisites need not be finished to write this plan. Implementation starts only in a free slot with no ready main-project work, yields to that work, and stops on a missing required prerequisite rather than substituting a fake.

## 1. Done checks as commands

### Execution and judgment contract

These are **future commands**, not claims about today's crash-sim CLI. Section 7 owns every new test, example, fixture and example flag below. They follow the numbered command/output/PASS convention described for Stage 6 in `SPEC_CHECKLIST.md` and used in `docs/nodes/2.3.md`. The workload's `docs/STAGE6.md` is outside this worktree and was not read; the starting brief must reconcile the exact interface with it.

Run from the Broadsword root; `build/bin/broadsword.exe` is the installed Broadsword. For a task checkout, insert `--task <id>` after `crash-sim` and record that checkout's SHA and the job's build-source identity. Never judge one commit using another checkout's executable. No bare cargo, shell pipelines, directory changes or nested Broadsword jobs.

Use `scripts/node_check.py` to execute one block at a time with its `--timeout` set to the current `done_check_timeout_seconds` required setting in `broadsword.toml`. The runner supplies the external-process timeout and captures each block separately under `scratch/node-checks/3.2/`; the redirects below also describe distinct output names for direct execution under the same orchestrator timeout. Do not execute an unbounded copy of a command. The runner strips redirects when capturing output itself (`scripts/node_check.py`, `build_argv` and `run_command`). Do not run human or timing checks in an unattended `--all` batch.

Every automatic positive check also requires exit zero. Missing/empty output, a missing test, zero tests, missing fixtures/settings, refusal, timeout, cutoff, NaN/inf or any earlier failure is FAIL, even if a success token appears. `contains` below is compatible with `scripts/node_check.py`; it is not permission to ignore the exit status. Free-text human/quiet-board rules require judgment and must not be reported as mechanically passed.

Each numerical test prints labelled actual/reference/error/tolerance values and the fixture ID. The harness prints a success token only after a nonempty, exact expected case inventory has been evaluated. Tests exercise the library entry points directly, not just an example. All numeric gates and run sizes are required settings proposed in section 4, not literals in solver/test code. SI units throughout.

### 1. Material and state boundary rejects invalid input

```check d1
build/bin/broadsword.exe test crash-sim > scratch/n32-d1.txt 2>&1
PASS: contains test deform_input_contract_rejects_invalid ... ok
```

S4 creates this test. It checks the single constructor/validation boundary used by library callers and the example: signs, finiteness, zero/negative mass or area, inconsistent strain ordering, overflow-prone combinations, timestep, indices, missing/duplicate/unknown settings and oversized inputs. Invalid application leaves the prior state unchanged and returns a named error. The valid numerical band and resource limits are specified before solver work, not inferred from whichever inputs happen to pass.

### 2. FEM soft-body reference patch

```check d2
build/bin/broadsword.exe test crash-sim > scratch/n32-d2.txt 2>&1
PASS: contains test deform_tetra_patch_matches_reference ... ok
```

S5 tests a small-strain constant-strain tetrahedron against independently calculated affine displacement, strain, stress and nodal force fixtures (S3). Rigid translation produces zero strain; rigid rotation is tested only within the formulation's documented small-rotation band. This is a FEM kernel milestone, not proof of a large-deformation vehicle FEM solver. Each quantity uses its dimensionally appropriate mixed tolerance from section 4.

### 3. Cloth response

```check d3
build/bin/broadsword.exe test crash-sim > scratch/n32-d3.txt 2>&1
PASS: contains test deform_cloth_patch_matches_reference ... ok
```

S6 tests a pinned membrane under a prescribed affine stretch against exact edge-force/energy references, plus unloaded rigid motion and a sag/release finite-state smoke case. Reference-force agreement, pin invariance and no compressive membrane resistance are automatic gates; realistic folds, bending and self-contact remain later work, not claims made by this patch.

### 4. Plasticity, unloading and irreversible beam breakage

```check d4
build/bin/broadsword.exe test crash-sim > scratch/n32-d4.txt 2>&1
PASS: contains test deform_axial_cycle_matches_reference ... ok
```

S7 uses S3's load/unload/reload coupon: force, residual extension and dissipated work agree with a separately derived piecewise-linear elastoplastic law. One case stays elastic, one yields without breaking, one passes the failure strain and disconnects exactly once. Unloading cannot heal plastic strain or a broken connection. The failure law is a proposed model, not a claim to calibrated automotive steel.

### 5. First car-wall capability: lighter node-beam car

```check d5
build/bin/broadsword.exe run crash-sim -- cargo run --offline --release --example deform_check -- --case wall > scratch/n32-d5.txt 2>&1
PASS: contains deform-wall: PASS
```

S8 creates the example and `--case wall`. It executes the S3 manifest's lighter car against a fixed rigid wall, with measured initial mass/energy and labelled final crush ratio, permanent set, penetration, energy ledger residual, topology changes and finite-state counts. It prints the token only after the configured simulation duration and all gates: nonzero prescribed forward motion, wall contact, crush in the configured band, positive permanent set after unloading, penetration and ledger residual within limits, no mass loss and no invalid state. A failed or partial run must not leave a PASS report.

The S3 manifest freezes geometry, node/beam counts, material, wall, speed, seed and units before implementation; it records the required settings identity for timestep/duration and rejects disagreement rather than becoming a second configuration source. No input count is silently reduced to meet timing. The crush band is a proposed visibly non-rigid yet non-collapsed sanity band (section 4), not a match to a production Camry.

### 6. The evaluator can detect behavioural failure

```check d6
build/bin/broadsword.exe test crash-sim > scratch/n32-d6.txt 2>&1
PASS: contains test deform_judge_rejects_bad_reports ... ok
```

S4 creates this test and a scratch-only result evaluator. Feed the same evaluator an independently authored valid report and reports with zero crush, excessive penetration, non-finite numbers, absent energy terms, an empty sample stream, duplicate cases and a truncated last frame. Each invalid report must return its named failure, not merely exit for a parse/compile error. ### 7. Real-time solver budget (quiet board)

```check d7
build/bin/broadsword.exe run crash-sim -- cargo run --offline --release --example deform_check -- --case wall --timing > scratch/n32-d7.txt 2>&1
PASS: (quiet board) exit zero; deform-timing: PASS; nonempty complete samples; p99 frame-work seconds <= 1 / frame_hz; simulated seconds / measured wall seconds >= 1
```

S8 creates `--timing`. Same manifest and d5 gates, release build, fixed timestep and deterministic seed; no adaptive removal of work. Warm up on a separate run, reset to the initial car, then measure complete crash repetitions with `Instant` until the configured sample window is covered. Include impact and failure work, not just a settled car after warmup; reject a window without impact samples. Frame work includes every substep, contact, deformation, breakage and frame-state packing; exclude compilation, warmup and file writes, label them separately. Print sample count, window duration, total wall time, p50/p99/max, timestep and fixture identity. Define p99 as the sorted sample at `ceil(0.99 * count)`, using one-based indexing.

The target is the proposed interactive update rate in section 4. Also measure sustained simulated/wall time so sparse fast frames cannot hide a growing backlog. Record `broadsword status` evidence immediately before/after; no builds, tests or reviews may overlap. Loaded or interrupted runs are invalid and must be repeated, not averaged into a pass. This is a **CPU solver** budget, not a claim about end-to-end viewer frame time; viewer integration and profiling are required later.

Include a side view and a topology overlay; attractive silhouettes alone do not prove correct physics. Record rejected features and follow-up tasks too. No agent can supply Lazlo's approval. Any later vehicle imagery is context only until its use is approved.

### 9. First step toward real internal structure: section-bearing members


### 10. Second structural step: joints can fail

```check d10
build/bin/broadsword.exe test crash-sim > scratch/n32-d10.txt 2>&1

```

S10 tests a weld and a bolt coupon against S3's independently authored stiffness/strength law, with below/at/above-threshold cases and combined loading. These are declared simplified laws until joint calibration data is obtained.

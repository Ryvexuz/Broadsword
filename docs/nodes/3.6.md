### 1. Graph-driven mesh operations and attribute scripting

```check graph
build/bin/broadsword.exe run procedural-geometry -- cargo run --offline --example node36_check -- --case graph > scratch/node36-graph.txt 2>&1
PASS: last line == NODE36 graph PASS
```

Requires primitive, transform and repeat nodes, typed connections and a
per-face attribute script. Changing the upstream width must change mesh
coordinates and scripted attributes; an unchanged sibling branch must not
re-evaluate. Cycles, type mismatches and invalid scripts fail with named
errors. This proves mesh operations run on the graph, not a canned exporter.

### 2. Save, fresh-process reload and independent parameter instances

```check asset
build/bin/broadsword.exe run procedural-geometry -- cargo run --offline --example node36_check -- --case asset > scratch/node36-asset.txt 2>&1
PASS: last line == NODE36 asset PASS
```

Save the building subgraph, close its creating process, load only the asset
in a fresh worker, instantiate it with default and changed width, floor
count and material-tag parameters. Verify declared types, ranges, defaults,
stable parameter IDs, internal graph, scripts and output port survive.
Compare geometry with the independent fixture oracle, not pre-save output
alone. Two instances must not share mutable parameter state. No original
scene, source graph, absolute path or external executable may be needed.

### 3. Automation parity, hostile inputs and bounded failure

```check safety
build/bin/broadsword.exe run procedural-geometry -- cargo run --offline --example node36_check -- --case safety > scratch/node36-safety.txt 2>&1
PASS: last line == NODE36 safety PASS
```

Create, edit, query, save and reload the same graph via the public automation
commands used by the eventual editor; compare results with the direct API.
Malformed assets, unknown versions, duplicate fields/IDs, missing ports,
non-finite values, invalid ranges and resource exhaustion must be named
failures without changing the prior graph or saved asset.
Scripts have no filesystem, process or network access.

### 4. Reuse demonstration — HUMAN: Lazlo

```check reuse-human
build/bin/broadsword.exe run procedural-geometry -- cargo run --offline --example node36_check -- --case reuse-human > scratch/node36-reuse-human.txt 2>&1
PASS: HUMAN Lazlo approves the saved building asset in a fresh scene, edits exposed parameters without editing internal nodes, and confirms distinct valid buildings and preserved scripted attributes; record revision and evidence paths.
```

The command prepares the asset, parameter manifest and inspectable meshes;
its exit code is not human approval. P10 supplies the inspection procedure
and records Lazlo's explicit verdict separately. Do not run this as an
unattended all-check acceptance. No timing threshold is proposed, hence no
check needs a quiet board. Any performance target needs a separate
quiet-board benchmark brief with a sourced budget.

Acceptance thresholds are exact for parameter metadata, integer topology,
attribute tags, error categories, instance isolation and evaluated-node
inventories. Axis-aligned building fixtures use integer dimensions exactly
representable in the declared numeric band: exact coordinate equality is
intentional. General transforms use a fixture-declared absolute-plus-relative
error rule against independently computed rational reference coordinates.
P3 must document and obtain Lazlo's approval for those budgets before code,
not tune them to observed output. No paper supplies an arbitrary tolerance.

## 2. Home

Proposed separate repository `procedural-geometry`, with one Rust crate
`procedural-geometry`, registered through Broadsword. It owns its graph
adapter, restricted attribute evaluator, asset format, examples and tests.
Paths in section 7 are relative to this future repository unless prefixed
`broadsword:`. This task creates no repo or crate.

ADR `docs/adr/0001-shared-core.md`, accepted option (a), governs: separate
repos, file formats as contracts. No Cargo dependency, path **or git**, on
another repo without a new ADR approved by Lazlo. Never link into
`projects/foundation`. Small local adapters and versioned conformance
fixtures are the initial integration route, not copied undocumented internals.

The desired node-graph runtime and mesh kernel may ultimately require
in-process code from 1.7/2.3's repos. That is an unresolved architecture
decision, not implicit permission. It fires ADR 0001's second-project
library-consumption concern (trigger 1) and potentially trigger 2 (a third
Rust project needing the same parser/math), or trigger 4 if numerics become
shared. Trigger 1 currently names the sim/`.bsn`; applying the same concern
here requires Lazlo's explicit new ADR, not pretending it already authorises
this dependency. Repeated bug fixes across copies also fire trigger 3.
P1 must select file-boundary integration or stop for that ADR and replan;
do not build a competing general-purpose node editor or mesh kernel here.

## 4. External needs

Each non-std choice is for Lazlo to decide before adoption:

- Prefer std-only initial parser/evaluator and integer fixtures. If using
  `serde`/`serde_json` for interchange, approve licence review, exact versions,
  Cargo.lock and vendoring first. Duplicate-field rejection remains required.
- Property/fuzz tools (`proptest`, `cargo-fuzz`/libFuzzer) are optional
  decisions, pinned and vetted; deterministic adversarial tests are required
  even if these tools are rejected. A C/C++ fuzz backend is an exception
  requiring Lazlo's approval, not a silent build prerequisite.
- No production C/C++ geometry or Houdini SDK planned. A future kernel or
  scripting library exception requires Lazlo, licence review and a new brief.
- Headless acceptance needs CPU only. Visual inspection can use an approved
  existing mesh viewer through files, not a Cargo dependency. If an editor or
  renderer is added this becomes graphics-heavy: system RAM and GPU memory
  are shared on this PC; Lazlo moves the work first and approves the budget.
- No tablet, gamepad, audio interface, second PC, paid service, network data
  or credentials required. Houdini is not required, and its proprietary
  assets must not be redistributed as fixtures.

P1 proposes required keys in the owning `broadsword.toml`: asset/graph/mesh
input and output paths, byte/node/edge/vertex/face limits, script instruction
and attribute limits, coordinate/dimension bands and worker timeout.
No hidden defaults or hard-coded limits. P3 adds reference-case paths,
seeds and numerical budgets. Orchestration timeout is a distinct setting.
These are future claims, not keys added by this documentation task.

## 5. Test harness

P2's example dispatches the exact section 1 case names and rejects all
others. Its case inventory must be nonempty and complete. It uses the same
public entry points as consumers, never mock geometry or saved success text.
The asset case launches its own fresh worker using a configured executable
path, with timeout, process-tree cleanup and bounded pipes; a grandchild
holding a pipe must not keep acceptance running indefinitely.

| Check | Proof and fixtures |
| --- | --- |
| graph | Tiny typed DAG with a building branch and unchanged sibling; hand-authored topology/coordinate oracle; script assigns floor and material tags; assert exact dirty-node IDs. |
| asset | Versioned building asset and metadata manifest; fresh-process reload; two independent instances; file round trip plus independent geometry oracle; inspect watertight closed boxes and valid indices, not only a hash. |
| safety | Direct lower-level parser, evaluator and automation entry points; malformed corpus; bounded generated graph cases; prior-state and destination-byte preservation assertions. |
| reuse-human | Fresh-scene workflow card, parameter manifest, exported meshes and labelled attribute dump; Lazlo inspects shape changes and reports approval or rejection. Images alone do not prove attributes or reuse. |

Use closed stacked boxes as the initial building (not a union requiring
booleans). Document separate closed components as intended topology.
Fixture oracle computes bounds, box counts, vertices, faces and floor tags
independently of production operations, using exact rational arithmetic.
Do not use generated production output as its own golden reference.

Hostile corpus includes huge counts/strings, overflow, empty data, negative
counts, NaN/inf, subnormal and near-cancelling transforms, unknown opcodes,
script loops/recursion attempts, duplicate keys, strings containing syntax,
CR/newlines, Windows drive and backslash paths, `..`, links and path
replacement after validation. Validate input once at the common constructor;
check computed values for finiteness before publication. Test smallest,
largest and cancelling accepted inputs against the independent reference;
explicitly reject values outside the documented band.

Save failure injection must leave the prior asset intact and report the
first error; temporary partial files stay confined to configured scratch.
Resource guards bound work before allocations/evaluation, not after output
truncation. Test failures halfway, link races and worker timeout/pipe leaks.
No script can escape through a helper or automation fallback.

Behavioural negative controls: disable dirty invalidation and graph must
report stale coordinates; omit parameter serialization and asset must report
missing width metadata; bypass instruction fuel and safety must report a
timeout failure rather than success. P2 tests its verdict logic with empty
inventories, truncated reports and deliberately wrong reference values.
Restore mutations and re-read the final diff before recording evidence.

## 8. Risks and size

The biggest risk is that separate graph and mesh repos cannot provide a
usable file-boundary contract without in-process dependencies. Resolve that
at P1 with Lazlo, not by sneaking in a path dependency. Prerequisite plans
are not delivered APIs. Asset versioning, attribute domains, numerical
bands and stable parameter IDs can all force rework.

Rough implementation size is the P1-P10 sequence above, with further briefs
likely for integration or security work if the small-slice estimate fails.
This is a planning estimate, not measured throughput. Full UI embedding,
Houdini compatibility, terrain generation, arbitrary scripting, booleans
and performance targets are outside this first building acceptance slice.
They do not remove mesh nodes, attribute scripting, reuse or automation
from the requirements. A headless test pass alone cannot replace Lazlo's
reuse verdict. Keep the roadmap **not started** until implementation evidence
supports a later status update through its own claimed task.

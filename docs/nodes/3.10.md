### Acceptance contract and thresholds

Scope the first exchange to a single closed, consistently oriented solid,
explicit millimetre units, and an approved STEP application protocol supported
by both chosen CAD applications. B3 freezes the protocol, schema, placements,
units, case inventory and tolerances **before** candidate output is examined.
No assembly, PMI or arbitrary feature-history preservation is implied.
Unsupported entities must give a named error, not disappear silently.

The primary fixture is an independently authored axis-aligned box of dimensions
`a=20 mm`, `b=30 mm`, `L=40 mm`, with the specified convex edge parallel to L.
The proposed fillet radius is `r=2 mm`: deliberately away from geometric
degeneracy, not a universal limit. B1 puts the operative radius in settings;
B3's reference manifest binds it to this case. The independent analytic
volumes are `a*b*L` and `a*b*L - (1 - pi/4)*r*r*L`. B3 computes and stores
high-precision reference intervals; tests must not use OCCT's result as oracle.
Endpoint positions, unit conversion, volume and the new cylindrical fillet
surface together distinguish a real edit from an unchanged STEP round trip.

Draft engineering budgets for Lazlo, **not an ISO conformance claim**:
length/point error at most `1e-5 mm`, and volume error at most
`max(cad_volume_abs_tol_mm3, cad_volume_rel_tol * abs(reference_volume))`,
proposed respectively `1e-4 mm^3` and `1e-8`. These allow exchange rounding on
the small fixtures while detecting unit mistakes and the specified edge cut.
The NURBS sample/derivative comparison uses the length budget after converting
derivatives to the manifest's dimensionless parameter convention. Tangency
uses the norm of the difference between consistently oriented unit normals,
at most the proposed dimensionless `cad_normal_tol = 1e-6`; this engineering
budget detects a sharp join while allowing derivative rounding. B3 must
demonstrate that reference interval widths are smaller than the corresponding
budgets and that the fillet's analytic volume change exceeds the volume budget.
All comparisons reject non-finite values first. Counts and schema/unit labels
are exact comparisons, not float tolerances. All budgets are required B1
settings, not literals hidden in tests; changing one requires reference review.
The supported numeric band and resource ceilings are also settings, chosen in
B3 with conditioning and memory reasons, not inferred from passing output.

**1. Fixture inventory and independent provenance exist.**
```check c1
broadsword test cad
PASS: contains test fixture_inventory_and_reference_intervals ... ok
```
B3 creates this test. Require every named fixture, nonempty STEP payload,
source/licence/tool version, checksum, units, intended topology, reference
intervals and approved tolerance reasons. Reject a missing or duplicate case.

**2. Import an actual STEP solid, including unit conversion.**
```check c2
broadsword test cad
PASS: contains test step_import_preserves_solid_and_units ... ok
```
B6 creates this test through our public API. Print case IDs, transferred
roots, solid count, bounds and volume against B3's analytic references.
Both millimetre and equivalent metre fixtures must describe the same solid;
an open shell must not be reported as a solid. Require exactly one valid,
closed solid for these fixtures, because that is their authored topology.

**3. Fillet the selected imported edge, not a replacement primitive.**
```check c3
broadsword test cad
PASS: contains test imported_edge_fillet_changes_geometry ... ok
```
B7 creates this test. Select by B3's geometric predicate and require exactly
one matching edge; an ambiguous or stale handle fails. Require a successful
kernel operation, a valid closed result, the requested radius and tangency,
and the independent post-fillet volume interval. Print before/after values
and witness points. Do not freeze OCCT edge indices or require arbitrary
topological numbering to survive a rebuild. A failed edit leaves the original
shape unchanged and returns no success-shaped output.

**4. NURBS are exposed as surfaces, not silently tessellated.**
```check c4
broadsword test cad
PASS: contains test rational_surface_matches_independent_samples ... ok
```
B8 creates this test for a rational quarter-cylinder patch, including interior,
boundary and repeated-knot samples. Compare points, derivative vectors and
surface domain to B3's independent rational-surface reference. Round-trip that
surface in STEP without replacing it with facets; do not call a bare open
surface a solid. Also test a closed curved solid fixture with a NURBS face.

**5. Export and re-import the modified solid without lossy repair.**
```check c5
broadsword test cad
PASS: contains test filleted_step_round_trip_preserves_geometry ... ok
```
B9 creates this test. Import B3's box, fillet it, write STEP into the test's
unique scratch directory, then read that file with a fresh kernel context.
Check protocol/units, solid validity, radius, bounds and analytic volume.
Byte equality is not required: STEP entity order and timestamps can change.
Success from the same OCCT reader is necessary, but does **not** prove c8.

**6. Lowest-level boundary fails closed on bad and limit input.**
```check c6
broadsword test cad
PASS: contains test kernel_boundary_rejects_invalid_and_limit_inputs ... ok
```
B5 creates the boundary test and B6-B9 extend its case inventory. It must
exercise the lower-level binding/worker directly, not just an example's
argument parser. Section 5 defines hostile, numeric, lifetime, process and
partial-write cases. Print attempted/rejected case IDs and retained-state
evidence; fail if any expected case is absent.

**7. Produce the actual interoperability artifact through the public API.**
```check c7
broadsword run cad -- cargo run --offline --example acceptance -- --produce
PASS: contains cad-exchange: READY
```
B10 creates `examples/acceptance.rs` and its `--produce` flag. In a new
configured scratch run directory it performs import -> edge fillet -> STEP
export -> fresh-context validation, then emits READY only after closing all
files and writing a complete manifest. Print relative paths, source revision,
native version/build identity, fixture and output hashes, measurements,
reference intervals and settings. Fail rather than overwrite an existing run.
The exported file must be the modified solid, not B3's input or a golden.

**8. Other CAD opens that exact export correctly (human: Lazlo).**
```check c8
broadsword run cad -- cargo run --offline --example acceptance -- --verify-human
PASS: (human, Lazlo) the c7 STEP opens correctly in the approved other CAD applications, with evidence bound to its hash and source revision.
```
B10 creates `--verify-human` and the record schema. It rejects absent,
incomplete, stale or mismatched records; its zero exit only validates the
record, never substitutes for Lazlo's judgment. B10 tests those refusals.
Lazlo opens the file in FreeCAD as an accessible smoke test and in an approved
**non-OCCT-backed** application as the independent exchange check. Record
application/version/importer, file hash, explicit units, solid-validity report,
dimensions, fillet radius and volume against the same budgets, plus screenshots
and Lazlo's verdict. Visual appearance alone or FreeCAD alone is insufficient.
If no independent application/licence is available, c8 stays unverified.
Free-text PASS rules are judged by hand by node_check, not automatically passed.

## 2. Home

Proposed home under **accepted ADR 0001 option (a)**: a separate repo registered
as `cad` (proposed main-checkout location `projects/cad`), containing the
`cad-kernel` Rust crate, a private native boundary and the acceptance example.
Its own interface owns shape/edge handles, units, validated parameters and
`CadError`; public signatures never expose OCCT classes or handles. STEP and
the versioned evidence/fixture manifests are file-format contracts. B2 creates
the crate and all module declarations before parallel implementation.

No Cargo `path` **or git** dependency on numerics, render, crash-sim,
Broadsword or another node's repo is planned. No link or dependency into
`projects/foundation`. Native vendoring is external-library provisioning,
not a Cargo dependency on another project's working tree. Broadsword passes
validated settings to the workload as a versioned data contract (B1/B2),
not by linking its crate. B1 is a separate Broadsword task, never one
cross-repo queue entry.

`docs/adr/0004-roadmap-repo-map.md` proposes W/cad but is **Proposed**, not
permission to invent that workspace. Before B2, Lazlo confirms separate-repo
placement or approves a new ADR and migration. Reuse of 2.8 as a library would
fire ADR 0001 trigger **4: a numerics core is needed by two projects**, and
possibly trigger **2: a third Rust project needs the same math/parser**.
Follow ADR 0001's F5/new-ADR route (its proposed ADR 0002; coordinate ADR 0004),
with Lazlo deciding; never work around it using a main-checkout path.
Live shared CAD/scene data would also require ADR 0004's proposed T6 decision.
Until then use local wrapper arithmetic and portable reference files only.

### Conditional OCCT exception and other decisions

- **OCCT:** mature specialist C++ B-rep/NURBS/fillet/STEP implementation,
  identified by the roadmap. Licence reported as LGPL-2.1 with the OCCT
  additional exception; verify the exact release's `LICENSE_LGPL_21.txt`
  and exception text at https://github.com/Open-Cascade-SAS/OCCT .
  Prefer unmodified dynamic DLLs, not static linking. Distribution requires
  the actual notices, corresponding-source/relinking arrangements and legal
  review of the pinned licence, not merely this summary.
- **Build once on this PC:** B4 defines an approved release/checksum manifest,
  MSVC/CMake toolchain identity, architecture/runtime/link flags, minimal
  modeling/STEP modules and an offline recipe. Disable visualization, examples,
  tests and optional components not needed by the slice where supported.
  The orchestrator provisions one immutable native install under the configured
  shared native path, through Broadsword, after approval. Ordinary worktrees
  link it and build only their thin shim; they never download/rebuild OCCT.
  Record actual install/build sizes then, not guessed sizes here.
- **Binding choice:** first evaluate the pinned Rust wrapper against that
  shared install. Fallback is a small owned C ABI shim plus Rust `extern`
  declarations using std only on the Rust side. MSVC compiles the shim;
  C++ exceptions must be contained before crossing the ABI. A `cxx`, `cc`,
  `bindgen`, hashing, TOML or property-test crate is another Lazlo decision,
  not an implicit dependency. The first implementation can use std tests,
  deterministic case generation and an approved system SHA-256 tool.
- **Std-only alternative:** authoring a robust STEP/B-rep/fillet kernel is
  specialist multi-year work (roadmap Part 1's wrap-first rationale).
  A faceted mesh or box-only fillet would not deliver this node. If neither
  a mature Rust crate nor OCCT is approved, stop; do not quietly port OCCT.
- **Reference tooling:** Python stdlib Decimal for offline analytic references
  and SHA-256 is proposed in B3, not a runtime kernel dependency. An independent
  CAD authoring/import tool is also needed; pin version and fixture provenance.
  FreeCAD is reported LGPL-2.1-or-later with separately licensed components;
  verify its distribution. A non-OCCT CAD application may require a proprietary
  licence and a permitted STEP importer; Lazlo chooses and authorizes it.
- **Hardware/network:** CPU-only and headless except c8. No GPU API, tablet,
  gamepad, audio interface or second PC is needed. No runtime network data.
  Approved source/fixture acquisition is a separate network action, never an
  agent's automatic build fallback. Large CAD/viewer work can become
  graphics-heavy: this PC shares system/GPU RAM; mark such a later brief
  `gpu-heavy: yes` and have Lazlo move memory first under ADR 0003. This small
  headless slice is not GPU-heavy; do not allocate a renderer to prove it.

B1 must add required root `broadsword.toml` settings for native/tool paths,
fixture/reference/artifact paths, approved protocol, fillet radius, numeric
band, length/normal/volume tolerances, reference precision,
byte/topology/work/memory ceilings, worker timeout and evidence-record path.
Missing or ignored keys
fail; there is no system DLL search or silent default. Paths stay relative
to root in settings/manifests; resolved runtime paths are not hard-coded.
No such setting is added by this documentation task.

## 5. Test harness

Use std Rust integration tests through `broadsword test cad`; no required
test-framework crate. B2 defines the harness/worker protocol and `CadError`
variants; actual operations arrive later. Empty module scaffolds are not
passing implementations, ignored tests or fake backend success.
B2's harness writes labelled measurements directly to stdout and a unique
per-case scratch report, not only to libtest-captured `println!` output, so
successful runs expose their values too. Report writes and incomplete case
inventories are checked, not silently discarded.

| Check | Proof and fixtures to make |
| --- | --- |
| c1 | B3 inventory and provenance tests; independently authored box, unit-equivalent box, rational quarter-cylinder surface, closed curved solid, open shell and malformed/truncated STEP. Keep text fixtures small; list every file in the manifest. |
| c2 | Import references from analytic dimensions/volume, not another call to our writer. Inspect roots, units, transforms, closedness and validity. Add empty/no-root and unsupported-schema rejection cases. |
| c3 | Analytic edge-cut volume and radius/tangency witnesses; geometrically select the edge. Invalid radius, wrong-shape edge, ambiguous predicate and stale handle each produce a named error and unchanged source. |
| c4 | Independent high-precision rational-surface samples and derivatives, including repeated knots and endpoints; a valid NURBS face in a solid. Invalid knots, degree, pole/weight counts, zero/negative unsupported weights and out-of-domain parameters fail before FFI. |
| c5 | Semantic round trips for the filleted box and curved solid, fresh context, independently checked references; never byte-golden the STEP writer. Incompatible units/protocol and missing NURBS entities must fail. |
| c6 | Direct boundary tests, deterministic property cases, malformed-file corpus and the resource/lifetime cases below. Seeds and case inventory are frozen in settings/manifest; fuzz expansion is a later bounded brief, not a substitute for these tests. |
| c7/c8 | End-to-end artifact manifest; real external importer reports and human screenshots/checklist. Hash/record mutation tests prove stale or empty evidence is rejected. No screenshot-only automatic PASS. |

Put validation at the **single lowest Rust/native entry boundary** used by
tests, examples and helpers. Use opaque generation-tagged handles, explicit
ownership/drop rules and serial contexts until threading is proven.
Never let Rust panic or C++ unwind across FFI. Test repeated create/free,
use-after-close, null/invalid worker handles and a missing or wrong-version DLL.
All return-status/exception paths yield named errors; preserve the first error.

Native STEP parsing runs in a bounded worker, not in the controller.
Enforce input size before import and configured worker memory/time limits
before execution; bound returned topology and messages before allocation.
Test huge input, excessive entities, malformed comments/strings/references,
truncated records and unsupported external-file references without creating a
home-grown STEP recognizer that disagrees with the native parser.
The first release accepts only the approved local fixture/input scope; do not
advertise a general safe untrusted-file service on these tests alone.
Test a worker/grandchild retaining pipes after timeout, partial messages and
native failure half-way through export. Kill the whole worker tree, reject
cut-off replies, preserve failure evidence and never publish a partial STEP.

All artifact writes are scratch-only, create-new in unique run directories;
do not overwrite input or delete previous evidence. Validate Windows drive,
UNC, backslash, traversal, CR/newline and empty paths; test a link/junction
substitution between check and use. Use handle-based/no-follow confinement or
fail closed, not a string-prefix check. Shared native provisioning is locked
by resolved **install path**, not by project label, and published atomically;
a half-built install is unusable and retained for diagnosis.

Central constructors reject bad signs, NaN/inf, overflow, unsupported scales
and invalid tolerances before any state change. Check finiteness again on
values about to be applied from the worker. For arithmetic on caller floats,
test smallest/largest supported magnitudes and near-cancelling cases against
B3's independent Decimal intervals; include subnormal/overflow inputs outside
the approved band and require named rejection. Do not quietly flush them to
zero or tune a reference using the implementation under test.

**Behavioural sensitivity, not compile failure:** in disposable future task
trees, bypass the fillet and c3/c5 must report the wrong post-cut volume and
missing radius witness; disable unit conversion and c2 must report bounds/
volume mismatch; allow an invalid radius and c6 must report accepted bad input;
change the output hash and c8's verifier must report stale evidence. Restore
each mutation and re-read the diff. B3 also tests its comparator with a
deliberately out-of-budget reference and a deleted inventory entry, so an
empty case loop cannot pass. These are planned tests, not performed mutations.

## 8. Risks and size

Major risks: unverified Rust alternatives; OCCT/wrapper licence or maintenance
changes; ABI/runtime/DLL incompatibility; native build size and offline
reproducibility; stage/prerequisite mismatch; tolerance/conditioning errors;
unsupported STEP schemas and hidden repair; unstable edge identity;
fillet failure on real parts; worker confinement and memory limits; and a
human exchange gate blocked by independent CAD access. FreeCAD and our wrapper
can share OCCT bugs, which is why FreeCAD alone cannot close c8.

Open decisions carried forward: repo/workspace placement and ADR triggers;
2.8 readiness or explicit waiver; Rust-first evaluation and native exception;
exact pins/licences/toolchain; required settings and supported numeric band;
fixture authoring/protocol/provenance and frozen budgets; independent external
CAD application/licence and Lazlo's actual verdict. Nothing above marks them
approved or checked online.

Rough planning estimate: **20-35 small briefs total**, not a measured count or
computed progress statistic. The initial B1-B10 rows are starting slices;
settings integration, shared provisioning, FFI/worker hardening, STEP coverage
and fillet robustness may each need additional sub-300-line briefs. Re-scope
before dispatch if the ABI or safety work cannot fit. Do not present this as a
full general-purpose CAD kernel, full STEP certification or a timing promise.
NURBS, valid solids and genuine filleting remain requirements even if a
visually plausible faceted export could fool a viewer.

Close only when **import a STEP file, fillet an edge, and export a STEP that
other CAD software opens correctly**, supported by the mechanical evidence
and Lazlo's hash-bound human verdict. This draft does not declare that result.

### Numerical acceptance contract

These thresholds are **proposed engineering budgets for Lazlo to approve
in F3/F10**, not measured accuracy or numbers attributed to a paper.
F2 makes every budget, input bound, resolution, duration, seed and artifact
path a required setting in the fluids repo's `broadsword.toml`; F3 records
the accepted values and reasons in `reference/SUITE.md`. Missing settings
fail closed. Do not tune a budget after seeing a failed solver result.

- Dam break: a dry-bed Ritter shallow-water case before wall impact, using
  the analytic profile and front in section 6. Proposed relative front
  error and normalized height L1 error bounds are each `0.10`: a deliberately
  coarse first-solver budget including the shallow-water approximation and
  particle sampling, **not** an experimental uncertainty. Evaluate at all
  fixture times on both planned resolutions. A separate enclosed-tank case
  tests walls; Ritter is not a reference after reflection.
- Closed liquid tank: relative mass drift at most `1e-6`, measured from
  total particle mass for SPH and reconstructed occupied volume for FLIP.
  The small allowance permits summation and surface-reconstruction error;
  constant marker count alone is not a FLIP volume test.
- Projection: dimensionless divergence norm
  `dt * rms(div u)` at most `1e-5`, and relative linear residual at most
  `1e-6`. These are solver-quality budgets, independent of the much looser
  free-surface visual/height budgets. Zero right-hand sides use an absolute
  residual scale specified in the fixture, never division by zero.
- Advection/reference-image normalized error at most `0.02` for the smooth
  manufactured scalar case and analytic uniform-volume ray integral:
  a first discretization budget, not a promise of cross-GPU pixel identity.
  F3 specifies norms, masks and denominators; empty masks fail.
- Non-finite state, negative density/fuel, particles outside closed walls,
  absent requested frames, missing cases and success on an invalid input
  are forbidden exactly, not compared using a float tolerance. Numerical
  state is validated before publication, not repaired by silently clamping
  a failed simulation into a pass.

## 2. Home

Proposed home: a new, separately registered workload repo **fluids**, normally
at `projects/fluids`, with a single Rust library crate/package `fluids` and
the `acceptance` example. This is a proposal for Lazlo, not permission to
create the repo now. CPU-first solvers and a small in-repo volume renderer
keep this node headless; no existing renderer changes are prerequisites.

Under accepted `docs/adr/0001-shared-core.md`, option (a), **file formats are
the cross-repo contract; no Cargo path or git dependency on another repo
without a new ADR accepted by Lazlo**. Never plan a link into
`projects/foundation`, a Cargo patch workaround or a sibling-checkout import.
F1 defines versioned scalar-grid/particle-frame formats with units, axis
order, times and finite-value rules. A later renderer can consume files;
it must not import the fluids crate across repos.

This node needs the *capabilities* of 2.8 (bounded sparse pressure solves)
and 0.4 (bounded deterministic jobs). The initial proposal keeps small local
implementations, with independent reference tests, rather than consuming
their repositories as libraries. Before approving that duplication Lazlo
must review ADR 0001 **trigger 4, "A numerics core is needed by two
projects"**: 2.8's plan already names crash-sim and fluids as consumers.
If reusing common vector/parser code is proposed, also review **trigger 2,
"A third Rust project needs the same Vec3 or the same parser"**.
If either trigger applies, stop for the ADR 0002/F5 workspace decision
described by ADR 0001; do not treat copying or std thread use as a way to
evade that decision. No shared-library import is assumed by this plan.

## 5. Test harness

F2 supplies a bounded std-only harness used by library tests and the example.
All comparisons report case, resolution, norm, measured value, bound and
sample count; enforce the fixture inventory, never accept an empty iterator.
F3 documents the norm definitions, dimensionless scaling and nonzero
denominators independently of solver output.

| Checks | Proof and fixtures to make |
| --- | --- |
| f1 | Provenance/inventory tests on `reference/SUITE.md` and the named fixtures. Corrupt/remove a required row in an in-memory copy: inventory must fail with the case name. |
| f2 | Direct constructor/state-publication tests: negative/zero spacing or timestep, NaN/inf, subnormals, overflowing dimension products, empty/duplicate keys, excessive particles/cells/frames/bytes/iterations/workers, invalid boundaries and unsupported versions. Validate all bounds before allocation, arithmetic or state changes. |
| f3 | Manufactured gradient/divergence/pressure fields with exact small-grid reference values; analytic nullspace and zero-force equilibrium. Disable projection behaviourally: the divergent input must exceed the divergence budget, not merely fail compilation. |
| f4, f5 | `ritter.csv` contains independent profile/front samples and scheduled times; `tank.case` defines a closed-wall liquid fixture. Repeat at the configured coarse/fine resolutions and worker counts. Same seed/config must replay identically on the same build; cross-platform bit identity is not promised. |
| f6 | `advection.csv` contains manufactured scalar samples; `plume.case` specifies source, buoyancy and open-top boundary. Changing/removing the source or buoyancy must fail the corresponding density/centroid assertion. |
| f7 | `slab.csv` holds independently evaluated Beer–Lambert ray integrals and camera rays. Empty, uniform and translated densities prove sensitivity, not a golden copied from this renderer. |
| f8 | `fire.case` holds a closed-form source-only reaction and a coupled transport case. Disabling the reaction must leave fuel unchanged and fail the positive heat-release check. |
| f9, f10 | End-to-end simulation → frame serialization → CPU rendering → manifest validation, plus Lazlo's checklist. An in-memory missing/duplicate frame and a blank-image substitution must fail artifact validation. No benchmark timing gate. |

The configuration and frame readers are security-relevant bounded parsers.
Use a documented narrow TOML subset for settings unless Lazlo approves a
parser crate; reject unsupported syntax explicitly. Test comments/strings
that resemble keys, duplicate keys, CRLF and other line breaks, invalid
signs, huge lengths/counts, truncated records, trailing garbage, drive-letter
and Windows-backslash paths, `..`, absolute paths and links/junctions.
All paths remain under their configured root; output creation must resist
link replacement, refuse overwrite, and report a partial run as failed.
Do not delete old evidence. Write into a fresh configured scratch run
directory, publish the completion manifest last, and preserve the first
error even if cleanup or output reporting also fails.

One validated constructor owns physical input bounds; one publication gate
checks finiteness of values about to be applied. Test both directly, including
smallest/largest supported and near-cancelling values against independent
reference values with independently justified precision/error bounds, not
merely another evaluation using the same f64 arithmetic. F3 must document
which underflow/subnormal ranges are rejected and why; "any finite f64" is
not an acceptable supported band.
All work loops and output sizes are capped by required settings.
Worker errors propagate; no worker may silently drop a phase.
Use named errors for invalid settings, unsupported formats, out-of-band
inputs, resource limits, unsafe paths, non-finite state, nonconvergence,
worker failure and incomplete artifacts; preserve the original I/O cause.
If parallel execution needs a lock, key it by the actual output resource,
not a scene label. No subprocesses are required inside the harness.

## 8. Risks and size

- **Architecture/start gate:** 2.8's recorded stage is later than this node,
  and its shared-core need may force ADR 0002. Do not silently declare the
  prerequisite done, link foundation or duplicate a library to bypass Lazlo.
- **Benchmark mismatch:** Ritter is a shallow-water, pre-impact solution,
  not a 3D splash experiment. F3 must justify thin-layer geometry, sampling,
  front definition and time window. If those cannot support the proposed
  budgets, stop and rewrite the benchmark before implementation; do not
  loosen a failed check after the fact. Martin–Moyce remains optional and
  licence-gated, not an omitted required data source.
- **Scope:** SPH, FLIP, pressure boundaries, open-top smoke, rendering and
  toy fire are separate capabilities. Neither a successful liquid demo nor
  a pretty plume may silently drop the other method or fire.

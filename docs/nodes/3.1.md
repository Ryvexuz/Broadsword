### Proposed meaning of stable and identical (Lazlo decision D1)

B2 records these proposed settings, their units and reasons before results are
seen; they are acceptance choices, not measured capabilities or published limits.
All operational limits and paths become required flat `rigid31_` keys in the
Broadsword root's `broadsword.toml`, with no defaults. Float values are quoted
decimal strings, compatible with the existing flat parser. Fixtures describe
physical inputs, not alternative hidden acceptance limits.

- `rigid31_box_count = 1000`: exact roadmap count. Use one vertical column, not
  disconnected piles or a hidden arrangement of supported islands. Unit-edge,
  unit-mass dynamic boxes rest on one static plane; gravity, restitution and
  friction are explicit fixture fields. No welds, joints, kinematic boxes or
  forced sleeping may hold this fixture up.
- `rigid31_step_seconds = "0.008333333333333333"`: proposed fixed timestep,
  chosen to resolve contact settling, not a real-time promise.
  `rigid31_settle_steps = 2400` and `rigid31_observe_steps = 4800`: proposed
  settling followed by sustained observation; judge every observation step,
  not just a favourable final frame.
- `rigid31_max_penetration_edges = "0.01"` and
  `rigid31_max_centre_drift_edges = "0.05"`: proposed limits relative to a box
  edge, for visible overlap and collapse respectively. Drift is measured from
  each body's intended lattice centre, including vertical compression, not a
  moving reference computed from the solver.
- `rigid31_max_linear_speed = "0.01"` (edges per second) and
  `rigid31_max_angular_speed = "0.01"` (radians per second): proposed residual
  motion limits during observation. Check support continuity, ordering, box
  count and finiteness throughout settling too; reject disappearing bodies.
  Independent oriented-box/plane and box/box geometry measures penetration,
  rather than trusting the solver's contact depth.
- `rigid31_numeric_relative_tolerance = "1e-10"` and
  `rigid31_numeric_absolute_tolerance = "1e-12"`: provisional small-case
  reference comparison using `abs(error) <= atol + rtol * abs(reference)`.
  Reason: allow f64 roundoff while detecting sign, axis and impulse errors;
  B3 must justify these against an independent exact reference before freezing.
  These are not the stack stability limits.
- Replay tolerance is **exact byte equality**, from "identical results".
  Initially promise the same executable, CPU target, compiler/FP settings,
  single-threaded schedule and initial state only. Cross-architecture replay
  is an open decision, not silently claimed.

## 2. Home

Proposed home: a new, separate repo registered as `rigid-body`, package
`rigid-body`, library `rigid_body`, with `src/` and integration tests. Lazlo must
approve the home before B1 creates anything. Do not retrofit the node-beam
crash simulator or change its frozen outputs just to get a starter solver.

Follow accepted `docs/adr/0001-shared-core.md`, option (a): independent code
copies; versioned scene/input/state files are the cross-repo contract.
**No Cargo path or git dependency on another repo without a new Lazlo-approved
ADR. Never plan a link into `projects/foundation`.** Local f64 vector,
quaternion, handles and broadphase code are owned here, not imported from
Foundation, numerics, render or crash-sim.

The potential need for 2.8 implementation code fires ADR 0001 trigger **4**,
"A numerics core is needed by two projects." Needing Foundation's same Vec3 or
parser as another consumer may fire trigger **2**, a third Rust project needing
the same Vec3/parser. A repeated math bug fires trigger **3**. Stop for ADR 0002
and its workspace spike if any applies; do not disguise reuse as a git
dependency or copied source link. This plan requests numerical conventions and
reference cases, not another repo's runtime library.

Later in-process rigid-body use by a game or viewer also requires that ADR
decision; ADR 0001 trigger **1** specifically concerns in-process sim/BSN use.
For now consumers exchange saved versioned files only. A live pipe, viewer and
new renderer integration are not needed for this node's done checks.

## 8. Risks and size

- **Acceptance ambiguity:** a vertical column is harder than a broad pile.
  D1 must accept the geometry, observation window and drift definition before
  tuning. The roadmap gives no physical tolerances. Never loosen them after
  seeing a failing run without an explicit revised decision and evidence.
- **Prerequisite/ADR gate:** 2.8 is not started and 0.3 is incomplete in
  `ROADMAP.md`; readiness is not waived by writing this file. Shared numerics
  or math needs may require ADR 0002 before B1, not an illicit dependency.
- **Solver scope:** GJK/EPA alone does not make a stable stack. Persistent
  manifolds, warm starting, friction, angular inertia and convergence at height
  may need substantial additional slices. Sleeping may optimize later, not hide
  an unstable acceptance scene.
- **Determinism:** unordered containers, contact ordering, compiler FP changes
  and hidden caches can defeat replay. Pin provenance and compare each step,
  not only final transforms. Cross-target equality remains an open D1 decision.
- **Oracle independence and valid band:** exact rational geometry is deliberately
  narrow. Expand the independently verified band before accepting more inputs,
  or ask Lazlo for a vetted reference tool. A second physics engine is not truth.
- **Infrastructure gaps:** the repo, root setting keys, oracle and process harness
  do not exist yet. They require future claims from B1-B3/B10; none is silently
  delivered by this docs-only task. Timing and GPU facilities are not blockers.
- **Size estimate, not a derived measurement:** budget roughly **20-35 briefs**
  to reach the Done-when, including setup, algorithm follow-ups, hostile/edge
  tests and review fixes. The first-brief table is an initial dispatch sequence,
  not a claim that ten sub-300-line changes can finish a robust physics engine.

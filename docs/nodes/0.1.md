# Node 0.1: Build and repo discipline

Roadmap "Done when": a fresh clone builds and tests in one command; CI runs on every commit; build and scratch folders auto-prune and never eat into the 20 GB reserve.

## CI half: what exists

`.github/workflows/ci.yml` builds and tests the `crates/broadsword` crate on every push (all branches) and every pull request. It has no secrets, no deploy steps and no third-party action except `actions/checkout`, pinned to a full commit SHA. The repo pins no Rust toolchain (no `rust-toolchain` file), so the job uses the stable toolchain preinstalled on the runner. The crate has no dependencies, so nothing is downloaded beyond the toolchain; `--locked` makes the build fail if `Cargo.lock` is out of date.

### CI contract

`python -I -B scripts/check_ci_workflow.py` passes only if `ci.yml` is byte for byte the approved copy (the `APPROVED` text in `scripts/check_ci_workflow.py`), after CRLF line ends are turned into LF. Any other content fails, prints a unified diff against the approved copy and the line `ci.yml changed: review the diff, then update the approved copy in the same commit`. There is no YAML parser: four review rounds each found a YAML form a hand parser misread, so an exact pin is the only check that fails closed whatever YAML can express.

To change the workflow, change `ci.yml` and `APPROVED` in the same commit, and have the diff reviewed. The checker first self-tests the approved copy against these lines (change all three together):

- ci-triggers: push, pull_request
- ci-runner: windows-latest
- ci-build: cargo build --locked -p broadsword
- ci-test: cargo test --locked -p broadsword
- ci-checkout: actions/checkout@11bd71901bbe5b1630ceea73d27597364c9af683

The self-test uses exact substring checks on the approved copy, not a parser: `on:` is exactly `push:` and `pull_request:` with no filters, `runs-on:` is the runner, the only two `run:` lines are the build and test commands, the only `uses:` is the pinned checkout, it ends with a newline, and none of `$` (so no `${{ }}` expression or secret), `secrets.`, `secrets)`, `branches`, `tags`, `paths`, `types:`, `if:`, `continue-on-error`, `shell:`, `env:`, `working-directory`, `container:`, `services:`, `strategy:`, `defaults:`, a tab, a CR, `{`, `}`, `&`, `*`, `<<`, `---`, `...`, ` :` (a space before a colon), `?`, `|`, `>`, `!`, `"`, `'`, `[`, `]` or `%` appears in it. The self-test only catches gross mistakes in an edit of the pin; the guarantee is the exact match plus a reviewed diff whenever the pin changes.

The runner is Windows because the crate has Windows-only code (`#[cfg(windows)]` in `crates/broadsword/src/buildsrc.rs`).

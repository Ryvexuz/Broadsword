# Node 1.2: GPU abstraction (plan, ahead-work)

**Status: draft: rewrite when the node starts.** Written 2026-11-20 from `CAPABILITY_ROADMAP.md` Part 5 (node 1.2) and `ROADMAP.md` (row 1.2: `not started`). No code, no downloads and no repo exists yet. Everything below is a plan: the program names, flags and test names in section 1 are the ones the briefs in section 7 create, and they are not real until those briefs merge. The two backends and every numeric threshold are starting values (marked), to be confirmed by brief G9.

- Build (roadmap): wgpu/Vulkan layer for buffers, textures, pipelines and compute.
- Done when (roadmap): the same render shader and compute shader produce matching output on two backends.
- Needs (roadmap): 1.1. See section 3: the Done-when does not use 1.1 at all.

**Product intent this plan respects** (Lazlo, 2026-11-20): one unified tool, where modes (modeling, render, physics) are switchable crate groups over one shared core data model. So this layer owns **no scene, mesh or material types**. It takes bytes plus a layout description in, and gives bytes back. A mode keeps its data in the shared core and asks this layer to upload, run and read back. No mode may depend on another mode's internals; all of them reach the GPU only through this layer's public API. That keeps the API valid whether the code later sits in its own repo or becomes a workspace member (ADR 0001, option d2).

## 1. Done checks as commands

Run every command from the Broadsword root. `broadsword` means `build/bin/broadsword.exe`; inside a task add `--task <id>` after the project name. Never pipe a broadsword command; each one is redirected to a file in `scratch/` and the file is read. Programs run with the project folder (`projects/gpu`) as the working folder. `broadsword run` prints its own job lines (`job:`, `source:`, `checkpoint:`, `build source:`) first and `--- summary ---` and `run: ok (...)` or `run: FAILED (exit N)` last; "PRINTS" below means the program's own lines between them. `broadsword test` ends `test: ok — N passed, 0 failed`.

Program contract (created by briefs G3 to G9, see section 7): `parity` is `examples/parity.rs` in the `gpu` crate. Its flags: `--list-backends`; `--case <compute-int|compute-float|render>`; `--a <backend>` and `--b <backend>` (backend names `vulkan`, `dx12`, `gl`); `--max-ulp <n>`; `--max-diff <0-255>`; `--max-bad-frac <fraction>`; `--shader-hash`; `--inject-fault`; `--dump <folder>`. Exit code 0 means PASS, 1 means a compared value broke its threshold (FAIL), 2 means a usage error or a missing backend (never a silent skip). Every flag a check uses is required; the program has no defaults for thresholds (a missing one is a usage error, exit 2).

**Each check runs when its own brief group has merged** (the "Runs when" line under each check). A check that needs a later group is not run early and is not counted as failed early; the node is done only when all ten pass after G10.

Blocks marked **[human]** need Lazlo. Blocks marked **[quiet board]** are timing and run only when no other job is running (confirm no other job is running first, by listing the running jobs as in check 1.2.9).

### 1.2.3 The integer compute shader matches on both backends, bit for bit

```check 1.2.3
build/bin/broadsword.exe run gpu -- cargo run --offline --release --example parity -- --case compute-int --a vulkan --b dx12 --max-ulp 0 > scratch/gpu12-3.txt 2>&1
PASS: the file contains `run: ok` and the program line `parity compute-int a=vulkan b=dx12 n=1048576 a_vs_cpu=0 b_vs_cpu=0 a_vs_b=0 result=PASS`. Every one of the three mismatch counts is 0 (integers are exact, so no tolerance), and n is 1048576.
PRINTS: the line above, one line, and nothing else from the program except warnings.
```

The kernel is a workgroup prefix sum plus a histogram of 1,048,576 `u32` values produced by a seeded xorshift (fixed seed in code, so the input is the same on every run and every backend). The expected values come from a std-only CPU reference in `src/reference/compute.rs`, so "matches" has an answer that no GPU produced.

Runs when: G9 has merged (needs `--case`, G7 and the G5 reference).

### 1.2.4 The float compute shader matches on both backends within an ULP bound

```check 1.2.4
build/bin/broadsword.exe run gpu -- cargo run --offline --release --example parity -- --case compute-float --a vulkan --b dx12 --max-ulp 16 > scratch/gpu12-4.txt 2>&1
PASS: the file contains `run: ok` and the program line `parity compute-float a=vulkan b=dx12 n=65536 max_ulp_a_vs_cpu=<x> max_ulp_b_vs_cpu=<y> max_ulp_a_vs_b=<z> result=PASS` with x, y and z each at most 16.
PRINTS: the line above, with the three measured values, one line.
```

Kernel: a 256 x 256 f32 matrix multiply (each output is a sum of 256 products), checked against an f64 CPU reference rounded to f32. **Threshold 16 ULP is a starting value, not a measured one.** Source to cite when the node starts: the WGSL specification section "Floating Point Accuracy" (https://www.w3.org/TR/WGSL/), which allows fused multiply-add and gives per-operation error bounds (the exact bounds were not checked for this draft). Brief G9 measures the real spread on this PC, sets the bound to the measured maximum with a stated margin, and writes the number and the measurement into `docs/NODE12.md` in the gpu repo. A bound that is loosened later needs a reason there.

Runs when: G9 has merged.

### 1.2.5 The render shader matches on both backends within a pixel tolerance

```check 1.2.5
build/bin/broadsword.exe run gpu -- cargo run --offline --release --example parity -- --case render --a vulkan --b dx12 --max-diff 2 --max-bad-frac 0.001 > scratch/gpu12-5.txt 2>&1
PASS: the file contains `run: ok` and the program line `parity render a=vulkan b=dx12 size=256x256 bad_a_vs_b=<p> max_diff_a_vs_b=<d> bad_a_vs_cpu=<q> bad_b_vs_cpu=<r> result=PASS`. A pixel is "bad" when any channel differs by more than `--max-diff` (2 of 255). PASS needs p, q and r each at most 65 (0.001 of 65,536 pixels, rounded down).
PRINTS: the line above, one line.
```

Scene: a fixed set of 12 flat-coloured, depth-tested triangles into a 256 x 256 RGBA8 target, one vertex and one fragment entry point in `shaders/triangles.wgsl`. The CPU reference (`src/reference/raster.rs`) rasterizes the same triangles with the pixel-centre rule. Differences are expected only on triangle edges (rasterization rule and interpolation precision), which is why a small fraction of pixels may differ. **The 2 and 0.001 are starting values**: brief G9 measures the spread and sets them, with the reason written in `docs/NODE12.md`. Flat colours (no texture filtering, no MSAA) are used so the bound has a reason; the plan does not claim a bound for filtered or anti-aliased output.

Runs when: G9 has merged (needs G8 and the G6 reference).

### 1.2.7 The parity check can fail (planted fault)

```check 1.2.7
build/bin/broadsword.exe run gpu -- cargo run --offline --release --example parity -- --case render --a vulkan --b dx12 --max-diff 2 --max-bad-frac 0.001 --inject-fault > scratch/gpu12-7.txt 2>&1
PASS: the file contains `run: FAILED (exit 1)` and the program line `parity render ... result=FAIL`. `--inject-fault` flips one output pixel block on backend b after readback (code in `examples/parity.rs`, run only when the flag is given; the normal path is unchanged). If this command prints `result=PASS` or `run: ok`, check 1.2.5 proves nothing and every parity check is void.
PRINTS: one `parity render ... bad_a_vs_b=<p> ... result=FAIL` line with p above 65.
```

Same for compute: the planted fault for `compute-int` is exercised by the unit test `parity_compare_detects_one_flipped_value` (in `tests/parity_compare.rs`, counted in check 1.2.2's N).

## 2. Home

- **Repo and crate:** a new, separate repo `projects/gpu` with one library crate `gpu` (lib name `gpu`), examples `parity` and `bench`, and its own Cargo workspace (`[workspace]` in `Cargo.toml`, as render and crash-sim do, so it does not attach to the Broadsword workspace). Created by the orchestrator at Lazlo's approval (decision D1); no repo is created by this plan.
- **ADR 0001 (Accepted, option a):** separate repos, file formats are the contract, no Cargo dependency (path or git) on another repo without a new ADR, which is Lazlo's call. This node needs nothing from any other repo: the render and compute shaders, the CPU references and the scene are written inside `projects/gpu`, as copies where needed (for example `src/reference/raster.rs` is its own small rasterizer; it does not import `projects/render`). Never a link into `projects/foundation`.
- **When another repo needs this code it fires an ADR 0001 trigger.** Node 1.3 (vector renderer), 2.1, 2.5 and the render repo's move to the GPU all need `gpu` as a library. That is trigger 1 ("a second project must run ... as a library") and, once a third Rust project does, trigger 2. Either one means ADR 0002 and the move to option d2 (one workload repo, a Cargo workspace) before any of them depends on `gpu`. This plan does not plan that dependency and does not ask for it; section 8 lists it as the first thing that will break the plan.
- **File formats as the contract:** the layer's contract with other repos is data, not types: WGSL text files (`shaders/*.wgsl`, plain files other repos can read) and byte buffers with a layout description (`BufferLayout { stride, fields: [(offset, format)] }` written as text in `docs/NODE12.md`). This also fits the unified-tool intent: the shared core holds the data, and this layer only moves bytes.
- **Window or surface:** presenting to a window needs node 1.1's window. The Done-when is checked headless (offscreen texture and readback), so no window code is in this plan. A `Surface` module is a later brief, and when it needs 1.1's window handle it receives a raw handle value through the API; it does not import 1.1's crate.

## 4. External needs

All of the following except std are decisions for Lazlo. Nothing is fetched until he approves (network access and new dependencies are "ask first").

- **D1. A new repo `projects/gpu`** (plan only).
- **D2. Crates, from the Rust registry only, exact versions pinned (`=x.y.z`), `Cargo.lock` committed, licences checked on pinning:** `wgpu` (the GPU API layer; it brings its own shader translator `naga`, the Vulkan and DX12 backends and a few dozen transitive crates), `pollster` (blocks on wgpu's async calls), `bytemuck` (safe casts between typed slices and bytes; version 1.24.0 is already in the local Cargo registry cache). Versions are chosen when the node starts: the current wgpu release is not looked up in this plan, and its API has changed between releases, so the first brief reads that release's docs. Not needed for 1.2: `winit`, `raw-window-handle`, `image` (the PPM writer is std only), `glam` (no math types).
- **D3. Network once:** a one-time `cargo fetch` for those crates into the shared Cargo registry cache, by the orchestrator, after D2. After that every task builds with `--offline`. No per-worktree copy of the cache (AGENTS.md: one shared copy).
- **D4. Vulkan runtime:** the GPU driver provides it (no SDK is needed to run wgpu's Vulkan backend). The Vulkan validation layers (a separate SDK download) would help debugging and are optional and unplanned.
- **D5. C/C++ libraries: none.** wgpu's Vulkan and DX12 backends are Rust (they call the system's driver libraries). No C/C++ library enters the repo.
- **D6. What counts as "two backends":** the recommended pair is Vulkan and DX12 on the one GPU in this PC. If the PC has two different GPUs (an integrated one and a discrete one), a pair of different hardware is stronger evidence but is not required. Whether a software adapter (WARP) counts as the second backend is Lazlo's call; the plan assumes no.
- **GPU access and memory (graphics-heavy: yes).** This work uses the GPU and its memory. The PC shares memory between system RAM and the GPU, so Lazlo moves it first (the memory split is his to change; agents never touch it). The tests are small (a 1M-element buffer is 4 MB; a 256 x 256 target is 256 KB), so the node itself needs little GPU memory. The wgpu build does not: its debug build is large, and the shared build folder grows by an amount not measured here (assume several GB; check free space against the 20 GB disk floor before the first build in G2).
- **Hardware:** none beyond the PC's GPU. No tablet, gamepad, audio device or second PC.
- **Network data:** none. **Licences:** wgpu is dual MIT/Apache-2.0 and naga and pollster are MIT or Apache-2.0 (from memory; the licence of every pinned crate, including transitive ones, is read from its `Cargo.toml` when pinning in G2 and listed in `docs/NODE12.md`).

## 8. Risks and size

- **wgpu's API moves between releases.** A pin written now may not match what a model remembers. Mitigation: G2 reads the pinned version's docs before writing code, and the pins are exact.
- **Tolerances are guesses until measured.** The 16 ULP and the 2 / 0.001 pixel bound have no source yet. If G9 finds a larger spread than expected, the question for Lazlo is whether a looser bound still means "matching output"; the plan does not decide that for him.
- **Same GPU on both backends is weaker evidence than two vendors.** The CPU references reduce this but do not remove it (section 5). Decision D6.
- **Backends may not both open.** A driver without Vulkan, or a Windows install without DX12, fails check 1.2.1. Then the node is blocked on hardware, and the plan says so instead of substituting a fake backend.
- **Build cost.** A first wgpu build is long and the shared build folder grows; the disk guard (20 GB floor) applies, and G2's first build must follow a free-space check. Not measured here.
- **ADR 0001 trigger 1 fires as soon as a second repo wants this crate.** Nodes 1.3, 2.1 and 2.5 and render's GPU path all do. The plan works for this node alone; the next node that needs `gpu` stalls until ADR 0002 (Lazlo) moves the repos into one workspace. The API is data in and out and carries no scene types, so the code needs no change when that happens.
- **Unified-tool intent.** Any shader-visible data layout (vertex format, material block) will eventually be defined by the shared core, not by this layer. If the core's layout changes, that is a cross-shard change in the harness's terms. The layer's `BufferLayout` is the only place it appears, which keeps the blast radius to one type.
- **Size.** Ten briefs reach the Done-when (G1 to G10), about 2,000 changed lines in total if each stays near 200. Of those, 6 are code that a GPU must run and 4 are references, harness and docs. A usable layer for nodes 1.3 and 2.5 needs more: surface and window presenting (after 1.1), texture formats and samplers, bind-group reuse, a pipeline cache, error scopes and device loss handling, a real shader-module loader. A rough estimate is 6 to 10 more briefs after the Done-when, not planned here.
